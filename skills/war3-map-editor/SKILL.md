# Warcraft III 地图编辑与知识积累

为用户处理魔兽争霸 III 地图编辑、KKWE/YDWE、T/GUI 触发器、逆天函数、技能、物编和导入内容。优先交付可以在编辑器中继续编辑的 GUI/T；JASS 或 Lua 仅在 GUI 无法实现或用户明确要求时使用，并说明涉及部分。用户的明确要求优先；此 Skill 不是模型训练，也不保证其他设备或新会话总会自动加载。

## 开工先查资料与当前地图

按需读取用户 GitHub 知识库 [索引](https://github.com/gamdumlsndnx-eng/KKWE/blob/main/知识库-索引.md)。写技能时查 [GUI、属性与伤害](https://github.com/gamdumlsndnx-eng/KKWE/blob/main/触发器/技能制作规范-模块化GUI与属性伤害.md) 和相关专题；物编查 [技能承载与按钮位置](https://github.com/gamdumlsndnx-eng/KKWE/blob/main/物编/技能承载与按钮位置.md)。优先通过已连接 GitHub 工具获取当前版本；网络不可用时可查本机 `C:\codex\007\KKWE编辑器学习\知识库-索引.md` 及相关文件，并说明可能不是最新版本。不要依赖聊天上下文或把整个知识库一次性塞入上下文。

跨项目复用做法，不假设每张图都有参考图的 rawcode、函数、数据键、模型、玩家绑定和伤害模块。需求未写细时，以《一剑爆开天门》对应系统的作者确认设计与已核对逻辑为起点，核对目标地图后适配；静态追踪、作者确认和游戏验证分别标注，参考图专属规则不能自动推广。当前需求优先于旧说明，作者后续针对同一机制的明确更正优先于旧结论；启用 GUI 显示的是当前实现，可能与设计不同。关闭的触发器、灰色或禁用动作一般为样本/备份，不计入实际运行。源码学习问题需写明分类、触发器和分组；代码明确的内容先自行推断。

技能往往跨初始化、英雄、练功房、UI 词条、装备获得/吞噬、属性、伤害和物编等模块；先追踪实际相关的状态写入、读取与清理，再决定改动范围。换英雄或皮肤的 Q/W/E/R 冷却与英雄及吞噬装备、吞噬技能联动；用户确认参考图应按技能各自保留剩余冷却，不能只按按键位置把旧技能冷却赋给不同的新技能，也不能仅凭某一触发器暂未看到回写就认定故障。新地图按其自身实现和明确需求核对。

## 制作技能和物编

- 先确定触发时机与来源：攻击开始、实际伤害事件、伤害结算之后、受伤和死亡不等价。检查英雄/伤害马甲/召唤物、玩家归属、零伤害、事件先后及递归保护；以实测确定目标事件的真正时机。
- 使用单个任意单位或玩家的通用入口，逆天局部变量保存本次上下文，逆天运行触发器显式传递需要的玩家、英雄、目标、数值和马甲。持久状态绑定相应玩家或单位；避免为各玩家复制同构触发。局部数组、计时器和跨触发传参按当前版本接口核对。
- 查目标图是否已有属性、伤害计算、暴击、增幅和马甲模块；存在时正确对接，不存在就根据需求实现并说明差异。只转发固定伤害的 GUI 不能称为完整的伤害/属性系统。按技能需要明确基础值、缩放、伤害类型、来源、暴击、减免和叠加；不得臆造不存在的接口。
- 被动技能可按作者习惯使用已确认的月刃模板作为标识，物编单独核对技能名称、图标、按钮、等级与科技需求；空白图要检查是否继承原版要求及原生效果。模型、贴图、文本、地形纹理和导入路径都可能影响游戏内容；先查作用及依赖，不能只把导入当作美术资源。
- 写清每个持续实例的生命周期、组/计时器/特效/临时单位的所有者以及正常结束、最后一层耗尽、目标或施法者死亡等清理路径。需随时间淡出时处理动画和透明度，不在终点直接删除后声称有死亡动画。多人与交错场景必须按目标游戏规则验证。
- 多方向冲击波、剑气等若只是数量或角度不同，优先复用目标图中同语义的投射物模块并传配置；范围去重、往返/追踪、伤害和清理不同则单独处理。按需读取 [多方向投射物模块](https://github.com/gamdumlsndnx-eng/KKWE/blob/main/触发器/技能制作-多方向投射物模块.md)，不要复制整套同构触发。
- BOSS 技能默认先给玩家清晰预警，再延迟释放，留出反应和躲避时间；用户明确要求例外时按要求。预警形状、范围、方向和有效时间应与实际技能一致，具体延迟按技能和地图调整。按需参考 [BOSS 多段预警与范围控制](https://github.com/gamdumlsndnx-eng/KKWE/blob/main/触发器/技能制作-BOSS多段预警与范围控制.md)。

## 编辑器操作与验收

KKWE 在本机优先使用个人插件 `kkwe-map-editor:kkwe-map-editing` 和其 MCP，先 `ping`、确认地图和当前对象；编辑现有对象前保留可恢复备份。参考编辑器路径为 `C:\codex\007\参考文件\KKWE插件`；不要读取用户排除的 `C:\codex\007\分析记录`。插件可能没有新建地图或预摆单位能力，不要把开局创建误报为编辑器预摆。

按函数真实签名和参数类型写入，事后从编辑器读回 GUI 树及物编；不要调用已在此版本触发崩溃的 `validate_triggers`。当前工作约定由用户手动保存和游戏测试，除非用户明确改变要求。静态读回、保存编译、单人游戏、多人并发、长期资源使用是不同证据等级，逐项如实报告。

用户已授权将本领域可复用的文字知识写入公开仓库 `gamdumlsndnx-eng/KKWE`。对于实践中发现的重要修正，完成当前任务后将已确认规则、适用范围、证据位置与未验证项合并到最相关的知识文档；有冲突时更正旧内容，更新索引并读回。新图的私有素材、地图、访问凭证或可识别的私人资料不得因这项授权被自动上传；同步仅限用户授权公开的知识。重要的跨项目偏好可在用户明确要求时写入系统允许的个人记忆。知识更新是基于后续任务中主动维护文件，不是后台自主训练或模型权重改变。

本机 `C:\codex\007\KKWE编辑器学习\GitHub知识库` 是 GitHub 的离线镜像，不会自动与云端同步。成功更新云端后，核对对应本地文件是否有独立更改，再同步已确认内容并验证；发生冲突先保留两侧内容，不能直接覆盖。网络不可用时说明镜像可能过期，恢复连接后重新核对。
