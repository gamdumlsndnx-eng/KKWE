# 物编：技能承载、按钮位置与模拟伤害

本文件用于在 KKWE 制作 GUI 技能时确定技能物编、技能标识、按钮与伤害马甲。参考《一剑爆开天门-带物编》的只读物编和 GUI，以及作者对自己地图的说明；迁移到其他地图前核对依赖与需求。

## 技能承载方式

作者的默认制作方式是用触发器模拟技能效果和伤害；不依赖原生技能的数据完成整套效果。一般的被动技能标识可用月刃之类的技能物编作为承载，触发器按技能标识和等级判断后，调用相应的属性、伤害、特效及控制模块。通魔是可选的主动技能模板，不作为所有技能的默认前提。需要主动点击、指定目标或特殊操作时，先确认目标地图是否已有对应界面和操作方式，再选合适的承载；被动技能标识本身不等于主动选目标功能。

作者确认：其地图的“月刃（模板）”可以直接用于此类承载，不必因为物编里保留了原版弹射说明而额外调整。该结论针对作者所说的模板和用法；其他月刃衍生物编、不同单位或新地图是否需要调整，应结合其真实配置和需求确认，不单凭显示的旧说明断言游戏效果。

示例（只读观察，rawcode 仅用于定位源码，勿直接假定目标图存在）：

- 技能 `A00O` 名为“月刃（模板）”，以 `Amgl` 为基础；`A09A`“BOSSCunDangD3”也是 `Amgl` 衍生技能。编辑器显示的自定义修改并不覆盖它继承的所有字段。
- 单位 `o055` 的普通技能 `uabi` 包含 `A09A`。触发器【存档BOSS → BossCundangJN_Set】把 `A09A` 放入技能表 `BOSSCD_JN4[3]`；【存档BOSS → CundangBOSSD3（圆圈爆炸）】在伤害事件中检查伤害来源的该技能等级及其他条件，再进入模拟效果。物编负责提供可识别的技能标识，具体效果由启用 GUI 分支和相关模块处理。
- 这是一条已经追到的物编与触发连接，不表示全图技能都按同一入口运行，也不代替游戏验证。

创建技能时，应核对所属单位、标识和等级，以及是否为英雄技能、技能需求、图标、提示和命令卡位置。入口根据实际事件取得玩家或单位；效果逻辑拆成可复用的 GUI 模块，使用逆天局部变量和明确的运行触发传参。使用独立标识区分伤害来源，避免伤害事件重复进入自身。将原生技能字段当作界面和承载配置，不应误认为改物编说明就能改变模拟伤害。

## 按钮位置

作者提供的物编图使用 4 列、3 行的命令卡：横向 X 从左到右为 0～3，纵向 Y 从上到下为 0～2；例如 `(0, 0)` 在左上，`(3, 2)` 在右下。显示位置应结合目标单位现有技能、命令和实际界面确认，避免与其他按钮冲突。

当前 KKWE 的技能字段元数据中，普通按钮为 `abpx`/`abpy`，关闭按钮为 `aubx`/`auby`，学习按钮为 `arpx`/`arpy`。不同状态各有位置，不要把其中一组当成全部。编写前以当前编辑器的字段元数据为准；对本图的 `A00O` 查询 `Buttonpos` 未得到可用的有效值，因此不能把一次空读取当成实际坐标。修改时需回读相应字段并在编辑器界面核对，游戏中的最终显示仍需实测。

## 伤害马甲与空白图验收

源码里的 `e000`“马甲（不可移动）”与 `e002`“马甲（模拟英雄伤害）”都是 `ewsp` 衍生单位，已看到 `Avul`（无敌）和 `Aloc`（蝗虫）技能配置；玩家绑定的“分裂单位”“分裂单位2”是不同实例，即使使用相同物编类型也不能混为同一个单位，“分裂单位3”用于模拟英雄攻击。作者说明马甲伤害同时用于区分不同伤害、避免英雄自身伤害递归造成死循环，并提供更高自由度；多重箭使用独立来源和 0.01 伤害标识。不要把所有技能默认交给同一个马甲或照搬原图 rawcode。

在空白测试图制作具体技能前，先检查该图是否具备逆天函数、伤害事件、玩家绑定、属性和公共伤害模块；没有时按技能需求建立最小可用配套并说明差异。结合需求创建技能物编、相应角色的马甲及玩家归属，再写 GUI 入口、局部变量和模块传参，检查目标过滤、伤害来源、计时器与特效清理、多玩家数据隔离及递归保护。

通过 MCP 逐项读回技能、单位物编和 GUI，并检查触发之间的依赖；用户自行保存、重新打开和进游戏验收。若涉及多个玩家或交错技能，还要单独测试相应多人场景。编辑器读回、静态分析或一次游戏测试均不等于所有场景已验证。
