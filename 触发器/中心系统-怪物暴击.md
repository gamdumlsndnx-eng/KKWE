# 中心系统：怪物暴击触发器

## 来源和状态

- 地图：`一剑爆开天门-带物编.w3x`，SHA-256 `9FE03BDED0D2F25C74C44EA6608B44CDA6FA2B04EB0CA90F95976C07873B3434`。
- 触发器：`【中心系统 / BaoJi_Guai/*怪物伤害*/`。静态转换文件：`trigger/02-【中心系统/10-BaoJi_Guai__怪物伤害__.lml`。
- 以下为转换结果的静态阅读，尚未在源码地图编辑器逐项交叉核对，也没有实际运行或验证伤害数值。

## 结构与逻辑

1. 事件为 `JYDamageEvent`。它不是普通的原生受伤事件写法，需要继续确认定义及触发时机。
2. 条件要求伤害来源相对 `Player00` 不为盟友，且触发单位不是建筑。这里的玩家和单位判定以转换结果为准，是否覆盖所有阵营和伤害来源未验证。
3. 通过 YDWE 局部变量保存触发单位（`我`）、伤害来源（`怪物`）、来源单位类型（`nn`）及触发单位所属玩家（`玩家`）。本触发器中 `nn` 和 `玩家` 的后续用途需要结合完整系统判断。
4. 从伤害来源的用户数据读取键 `暴击几率`，当其大于 0 时，生成 1 至 100 的随机整数，并与 `R2I(暴击几率 * 100)` 比较。源码注释提及 `/1000`，但本段实际显示的运算是乘 100；字段单位不能仅凭注释断定。
5. 命中分支读取怪物的 `UnitStateDamageMax`，使用 `1.00 * 2.00` 和 `1.50 * 1.00 + 0` 等常数计算局部变量 `伤害`；该静态表达式的游戏数值仍需核对。
6. 从伤害来源所属玩家的数据读取键 `分裂单位`，并调用 `gg_trg_display_BJ` 传入 `我` 与 `伤害` 局部变量；之后由 `分裂单位` 对原触发单位发出 `UnitDamageTargetBJ`，攻击类型为混乱、伤害类型为普通。

## 依赖和待核验

- 需要追踪 `JYDamageEvent` 的注册机制、`暴击几率` 的写入位置、`分裂单位` 的创建位置和 `display_BJ` 的完整内容。
- 需确认追加伤害是否重新触发 `JYDamageEvent`，以及是否存在其他系统防止递归；不能仅从本触发器认定有或没有递归问题。
- 存档、物编、其他触发器及玩家同盟设置可能改变结果；不能把当前静态笔记当作已验证游戏规则。
