# 伤害事件与多人技能：制作及验证规范

用途：根据用户《一剑爆开天门》的 GUI 结构设计新的攻击、受伤、周期和连锁技能。用户未提供细节时，先查参考图对应技能与本规范，再按目标地图的系统和用户要求适配。本规范记录可复用接口、实际读到的顺序及待验证边界，不代表整张地图或所有多人交错情况已经验证。

## 先区分入口，再判断先后

1. 普攻、技能伤害、英雄受伤、怪物受伤和计时器是不同入口。先确认事件单位、伤害来源、所属玩家、目标、伤害类型、伤害值及过滤条件，再设计后续调用；不要将“攻击事件”直接视为“已经结算的伤害事件”。
2. 源码中 shanghai、jianshang_Hero、jianshang_Guai 和原生多重射 b1 等都使用 JYDamageEvent，但各自条件不同。shanghai 和英雄受伤可见入口要求事件伤害大于 0；怪物受伤入口要求大于 0.10 且受伤目标不是玩家 1 的盟友。多重箭用到的 0.01 不能假设满足所有监听器的条件。新地图须按实际伤害事件与阵营设置核对。
3. 同一个触发器内的启用动作有明确先后。例如英雄受伤触发先把该触发器进入时读取到的事件伤害放入局部变量，在其英雄分组内先处理法器、本命剑，后处理本触发器中的减伤分组。这个顺序不能自动推广为所有独立伤害监听触发器之间的执行顺序；其他监听器可能也修改事件伤害，实际先后须独立验证。
4. 英雄原始物理伤害、模拟英雄攻击的分裂单位3、多重箭的分裂单位2、普通技能所用马甲是不同角色。作者说明它们用于配合属性系统、简易防作弊、降低伤害递归，并防止伤害进入不对应的技能分支。技能新设计必须先对照目标图的真实对象与筛选条件；有马甲不等于所有递归已被消除。

## 周期技能和受伤叠层：不同输入，共用模块

- Meimiao100 每 0.10 秒枚举有效玩家组 WJZ，使用枚举玩家取得玩家编号、绑定英雄、伤害马甲与属性，再执行法器和本命剑相关分支。这样可以集中处理多个玩家，不需要把相同技能复制成玩家 1、玩家 2、玩家 3 三套。
- 法器焚炎的一个启用分支通过玩家与技能标识检查是否拥有、是否冷却；选择目标、计算伤害、创建效果并启用周期计时器。现有注释与一些参数未完全一致，选取目标与状态来源也还有未核实部分；这些数值和局部变量不能不加确认就移植。新技能应明确目标选择、持续时间、每次伤害、状态是否叠加、离开范围和死亡时的处理。
- 天罡（本命剑 BMJUR2）的英雄受伤分支按“玩家编号 + 技能标识”保存计数和累计伤害。GUI 在计数小于上限时累计本次伤害、增加 1 点护甲；已有计数达到上限时，下一次受伤移除累计护甲、执行范围伤害并清空相关计数。上限公式还读取多重数量和弹射数量。作者确认：从 0 开始且上限为 20 时，先累计 20 次，第 21 次受伤才爆发。不要只按注释简写自行改成第 20 次；改写时还须明确用于累计的是哪一个阶段的伤害，以及爆发那一次是否纳入累计。

## 嵌套伤害与暴击标记

已在源码备份中只读追踪到以下局部调用链：

1. 公共伤害计算 Dislpay_Sh 按玩家编号读取属性；技暴分组先将全局数组 ShangHai_BaoJi[玩家编号] 清为 0，符合技暴条件时设为 1，并通过逆天运行 display_Jibao。
2. display_Jibao 的 FQA148 分支要求拥有技能且不在冷却中；它先写入该玩家该技能的冷却状态，再调用公共伤害计算得到额外技能伤害，创建计时器执行后续效果，另由计时器解除冷却。这个先设冷却的设计可限制该技能再次触发，并不代表所有技暴附加效果都不会递归。
3. Dislpay_Sh 可见在技暴分组之后把本次局部伤害写入 ShangHai[玩家编号]。FQA148 调用后将该数组值读入本次局部伤害，再在周期计时器内对目标给伤害；但该计时器显示文字时仍读取全局的 ShangHai_BaoJi[玩家编号]。

不同玩家使用不同编号可分离对应数组槽位；同一玩家在一次技能尚未结束时触发另一次计算，仍可能对同一槽位写入。特别是 FQA148 额外计算可能嵌在外层技暴处理中，后续计时器又可能在其他技能计算后读取暴击标记。静态观察只能提出“伤害数值与暴击显示标记是否仍属于同一次计算”的验证问题，不能直接宣布结果错误或多人已安全。

新技能优先把一次计算的伤害、暴击标记、来源玩家、目标和必要的持续参数按执行实例保存并明确传参。若计算模块在返回前会嵌套运行其他伤害，单纯在最外层调用返回后读取一次全局标记未必能还原原来的标记；应查清模块内部读写并在回调前保存本次结果，或采用经过目标图验证的实例隔离方式。不要擅自改变原有公共模块，先在隔离图验证与现有玩法兼容。

## 多人及延时技能核对

1. 玩家状态应绑定实际玩家，单位状态绑定实际单位；持久的技能拥有、层数和冷却，不能误放进跨玩家共用的单个临时全局变量。
2. 逆天局部变量和传参按触发、计时器及调用分组逐一核对；参考编辑器注明局部数组不能直接穿透逆天计时器或逆天触发器，逆天计时器/注册触发器内不能等待。不同玩家和同一玩家的重入隔离仍需实测。
3. 延时期间考虑目标死亡、移出范围、状态刷新、多个效果重叠和资源清理。单位组要明确属于某次技能还是某个玩家，最后一个使用者结束后才能销毁；不要仅凭循环的最后一个编号就断言计时器实际结束顺序。
4. 按玩家决定的纯显示效果和改变真实游戏状态的操作需分清：局部显示分支不得未经同步就改变影响所有玩家的单位、伤害、属性或随机结果。具体接口与目标环境同步行为需另行核实。
5. 在独立可恢复测试图中，分别验证玩家 1 和 2 同时触发、同一玩家短时间触发两次、技暴触发额外技暴、伤害后目标死亡、计时器结束和清理；记录每次玩家、目标、伤害值和暴击标记，并由用户手动保存和游戏验证。事件注册顺序、联机同步和实际运行结果不能从 GUI 读取代替。
