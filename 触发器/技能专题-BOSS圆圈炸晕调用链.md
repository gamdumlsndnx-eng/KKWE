# 技能专题：BOSS 圆圈炸晕的静态调用链

范围：用户《一剑爆开天门-带物编》源码地图的隔离转换文本。所引行号对应 `source-analysis/converted-lni-diagnostic-2`，只用于复核 GUI 的转换结构；还未与实际源码地图编辑器逐项交叉验证，也没有游戏测试。不能把这里的行为推断当成全部技能系统已学完。

## 文件与初始化

- 主要 GUI 文件：`trigger/34-BOSS技能/06-BOSSA4__圆圈炸晕__.lml`。
- 初始化：`trigger/34-BOSS技能/01-BossJN_Set.lml:1-29`，一次性 3 秒计时事件中，将 `BOSS_sh` 的原值加 1，并设置 `BOSS_JN1[4] = A02A`；不能把“加 1”误写成“最终必为 1”，因为还要核对变量原值和其他写入。
- 物编转换：`table/ability.ini:12489-12492` 的 `A02A` 名为 `BOSSA04`、父对象 `Amgl`；`table/ability.ini:12613-12632` 的 `A02K` 名为“风暴之锤2秒”、父对象 `AHtb`。提示文字残留“5秒”描述，不等于实际技能时长；转换文本可能未包含完整继承后字段，需在物编中核验实际眩晕、伤害和投射物。

## 入口与放技能的条件

`06-BOSSA4__圆圈炸晕__.lml:1-28` 用 `JYDamageEvent`（该编辑器描述为“[马杀鸡] 任意单位受到伤害”）作为入口，检查伤害来源的 `BOSS_JN1[4]` 技能等级等于 1，且该次伤害大于 0。动作把伤害来源设置为逆天局部变量 `dw` 与 `我`，把触发单位设置为 `怪物`。这里变量名“怪物”本身不足以证明它一定是怪物；事件响应语义及单位实际归属需实测。

`29-183` 对来源单位的自定义整数键 `内置CD中` 和 `无法释放CD中` 均检查等于 0；两者通过逆天自定义值保存到单位上。代码分别以局部 `内置CD = 15`、`技能CD = 12` 为初始数值；拥有 `JN_Debuff[11]` 时，整数变量各除以 2。随后将两个状态置 1，分别启动 1 秒周期逆天计时器，计数后将对应状态置 0 并调用 `YDWETimerStartFlush`。循环的精确实际持续时间、计数初始值和整数取整均需要在本版本验证，不能简单把 15、12 直接断言为精确冷却秒数。

对照其他 BOSS 技能可找到同名两个单位自定义值键（例如 `03-BOSSA1__冲击波__.lml:29-44`）；其设计意图已由用户在下文解释，仍需逐项核对具体实现。

用户已确认这些状态是为了让同一只 BOSS 的不同技能共享禁止施法时间，避免同时释放，并解释会根据难度新增额外技能，因此施法后需要一段最低间隔，防止玩家承受过大压力。用户还提到本体技能与施法后的其他技能之间的区分；目前尚未逐项核清“内置CD中”和“无法释放CD中”分别对应哪一个具体职责、数值与优先级，不作额外推断。

## 预警、伤害和控制效果

1. `184-241` 取得伤害来源所属玩家，分别记录来源单位当前 X/Y 和受伤单位当前 X/Y；读取这个玩家自定义键 `分裂单位`。角度计算处读取的是 `Dy`、`Dx`（首字母大写），而此前设置的键显示为 `dy`、`dx`（小写）；在核实逆天键区分大小写前不推断最终朝向。代码还读取了 `jd1` 作为预警单位朝向，但本文件可见赋值与含义需另外确认。
2. `242-306` 设 `伤害参数=5.00`，以来源单位最大攻击力、`伤害参数`、`1.00 + 单位类型的自定义值“暴击伤害”`、全局 `BOSS_sh` 计算局部 `伤害`；拥有 `JN_Debuff[12]` 时再乘 3。这里只是观察到系数命名，不能据此认定本次攻击有独立暴击判定。
3. `307-366` 暂停来源单位并播放 `spell` 动画，在已捕获目标坐标创建 `TX_BOSS_Quan[1]` 单位作为警告、缩放 2.30，并安排 1.80 秒后移除。创建、移动和销毁漂浮文字的四项动作都明确为禁用，所以当前不能说有该漂浮字。
4. `367-493` 开启 1.60 秒一次性逆天计时器；计时后若来源单位存活，则解除其暂停，在原先记录的位置创建 `TX_BOSS_Quan[12]`，替换模型为 `war3mapImported\\JNNN02.mdx`、缩放 1.50，并安排 1 秒后移除。
5. 接着以原坐标和半径 440 枚举单位，筛选相对来源玩家为敌方、未死亡、非建筑的单位。对每个单位，以玩家关联的 `分裂单位` 作为 `UnitDamageTargetBJ` 的来源造成前述伤害，攻击类型 `Chaos`，伤害类型 `Normal`；另外在目标处创建 `TX_BOSS_Quan[100]` 马甲，添加 `A02K`，下达 `ThunderBolt` 指向该目标，并施加 1 秒计时生命。命令是否成功以及实际眩晕时长仍依赖物编、单位配置和游戏行为。

## 状态、清理与待验证事项

- `trigger/01-地图初始化/10-DayOff2.lml:86-109,214-249` 以不同玩家为对象保存相应预放单位作为 `分裂单位`。这说明该技能所用伤害源依赖全图初始化；它的具体设计目的和归属规则不能自行断言。
- 上述预警和效果单位使用定时删除，施法马甲使用计时生命；两个冷却周期计时器末端显式 `YDWETimerStartFlush`。1.60 秒一次性计时器的可见转换动作末尾没有显式同名清理动作；一次性计时器自身的销毁/缓存语义必须查逆天实现或实测，不能据此直接断言泄漏。
- 施法者死亡分支没有可见的恢复暂停动作；单位死亡后这一状态的实际处理、复活或重入影响均未验证，不应从静态读取认定有故障。
- 单位枚举函数的内部资源管理、定时器参数捕获和并发，以及转换文件中每个动作的父子分组，需要对照当前 KKWE 函数实现和编辑器 GUI，不能推断已验证。

## 请用户解释的两个设计问题

1. 对这个 BOSS 的范围伤害，你让玩家绑定的“分裂单位”作为伤害来源，而不是 BOSS 本身。这样设计主要是为了避免伤害事件连锁、区分伤害类型/来源，还是另有归属规则？
2. 用户已确认同一只 BOSS 的技能需要共享释放限制，以避免技能叠放造成过大压力；两个键各自的精确职责及持续时间，仍需继续追踪和核对。
