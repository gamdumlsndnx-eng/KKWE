# 技能伤害专题：技能暴击与 FQA148 被动

早期分析对象为《一剑爆开天门-带物编》的隔离转换结果，路径在 `source-analysis/converted-lni-diagnostic-2/trigger` 下；其后已补充源码编辑器只读核对。逆天传参的实际运行、并发、游戏伤害和显示仍未经游戏验证，编辑器内容与本地快照也不能仅凭地图名认定为同一磁盘版本。

## 源码编辑器补充核对：嵌套结果与冷却

已通过正在打开的《一剑爆开天门》源码备份和 KKWE MCP 复核【一些触发传输 → Dislpay_Sh（计算伤害）→ 技暴几率】、【display_Jibao（技暴传输）→ FQA148】的启用 GUI。该编辑器返回地图版本9803、保存次数6052；只读，未在游戏中验证。此处是对下方旧版转换分析的补充，不表示已完成并发或完整伤害系统验收。

- `ShangHai` 与 `ShangHai_BaoJi` 是按玩家 ID 索引的全局数组。外层计算先把该玩家的技暴标记置0；发生技暴时将其置1，再调用 `display_Jibao`。若 FQA148 满足条件，它又以同一玩家调用 `Dislpay_Sh`，内层计算也会重置并可能改写同一 `ShangHai_BaoJi[id]`。当前已读技暴分组里没有看到内层调用返回后恢复外层标记；因此外层后续读取的暴击标记有被内层结果覆盖的风险，尤其内外技暴结果不同时。不能仅凭静态调用树声称游戏中已复现或一定影响所有效果。
- 外层 `ShangHai[id]` 的写回位于 `display_Jibao` 调用之后的计算模块末尾，因此不能把“内层计算会覆写全局数组”简单等同于“外层最终伤害一定被覆盖”。需分别验证内层调用完成后的外层局部伤害、最终写回、技暴标记及其他触发器提前读取的时间。
- FQA148 先写玩家技能键的冷却标记，再处理计算与效果；按所读分支，局部 `time` 仅在 `技能冷却1 > 0` 时赋值为 `4 × (1-技能冷却1)`，之后用于启动计时器。本次没有找到同一已读触发内给 `time` 的无缩减默认赋值。作者此前已明确冷却缩减归零时应恢复基础时间；所以无缩减时是否准确保持4秒需要结合逆天局部变量实际语义及游戏测试，不能将未验证的零值或继承值当成事实。
- 制作类似嵌套技能时，为每次计算保存本次结果与技暴标记，调用嵌套技能前确定回写顺序；计时器效果应随实例保留需要的数据。多个目标共享一次技暴判定时，仍按作者确认分别应用各目标自身的 BOSS 加成；不为解决标记覆盖而对每个目标重新随机技暴。

## 一条可复核的调用链

用户说明：这一套公共模块通常只需要捕捉并传入玩家，随后根据玩家身上的自定义属性获取所需数据；玩家容易获得，所需参数较少，便于复用。作者已确认琉璃瓶的 80% 门槛使用玩家的“技暴几率”，普通“暴击几率”不能替代。这里是用户确认的设计思路，并非说每个模块都只需玩家；下述当前 GUI 的局部变量继承和游戏效果仍需验证。

1. `03-【一些触发传输/01-Dislpay_Sh__计算伤害__.lml` 没有独立事件（1–3 行），模块从逆天局部键读取 `s`、`玩家`、`伤害参数`，由玩家计算 ID；`伤害参数` 为 0 时改成 1（71–103 行）。接着按玩家自定义属性读取各类伤害与技暴状态（104–169 行）。这是复用的计算模块，不是每个技能各写一套伤害公式。
2. 同文件“技暴几率”段 1329–1383 行：先将 `ShangHai_BaoJi[id]` 设为 0；取 1 至 100 随机整数；满足局部 `伤害类型A = 2` 且随机数不大于 `R2I(技暴几率 × 100)` 时，将该玩家的暴击标记设 1，将当前局部 `伤害` 乘局部 `技暴伤害`，再调用 `display_Jibao`。调用动作中明确传入的局部参数是玩家，条件模式为 `tirggerexecute_notcondition`。这只是该段公式，不代表已理解完整伤害公式或暴击概率边界。
3. `03-【一些触发传输/03-display_Jibao__技暴传输__.lml` 无事件（1–3 行），读取玩家、转换玩家 ID、按玩家读取绑定英雄（4–22 行）；下面以“收纳盒”组织不同技能暴击后附带效果，按玩家 ID 与物品键查询已拥有、已吞噬等状态。它既处理独立加成，也可继续调用消息、属性、计算伤害和视觉模块，而不只是画暴击数字。
4. 该文件 109–149 行的 `FQA148` 段：字符串 `玩家ID + FQA + 148` 的 `已拥有` 为 1 且 `冷却中` 为 0，才把 `冷却中` 写为 1。注释说明技能暴击后沿直线造成攻击力伤害，基础冷却 4 秒。149 行之后从玩家自定义值获取分裂单位；冷却部分读取 `技能冷却1`，在该值大于 0 时将 `time` 设为 `4 × (1 - 技能冷却1)`，启动单次逆天计时器，结束时把同一个字符串对象的 `冷却中` 写回 0 并清理计时器（150–202 行）。
5. 同一被动在 203–296 行根据玩家 `伤害类型` 选择计算模式 `s=1` 或 `s=11`，运行 `Dislpay_Sh`，显式传 `玩家`、`伤害参数=1`、`伤害类型A=2`、`伤害类型B=2` 等；另有另一组子动作以及禁用的 `怪物` 赋值，必须在 KKWE 界面核实对应分组，不能把静态缩进直接当成已确认的调用次序和返回值。后续从 `ShangHai[id]` 读取到局部 `伤害`。
6. 该被动以绑定英雄位置、朝向和单位攻击范围建立视觉单位、单位组及移动逻辑；周期 0.02 秒、每步 30 坐标单位移动，并以 250 为半径枚举附近单位（297–498 行）。对敌方、存活且不在已命中单位组的单位，先入组，再将目标和伤害传给浮字模块，接着由分裂单位对目标施加伤害（500–579 行）。排除原怪物的条件是禁用状态（522–526 行），不能称为会排除原目标。
7. 周期结束分支中的直接移除视觉单位动作禁用，实际可见的是播放死亡动画、清空该单位自定义值、0.5 秒后移除单位、清空并销毁记录组、清除计时器（582–604 行）。这是源码主动处理单位与组生命周期的例子。

## 逐日剑法：路径、去重和结束

对照本地转换文件并只读核对编辑器当前 FQA148 分组：英雄当前位置与朝向用于生成视觉马甲，攻击范围大于800时，额外步数按 `R2I(攻击范围 - 800) / 30` 的整数运算计算。计时器每0.02秒走30，条件上限为40加额外步数；若初始计数为0且全程可通行，基础40步约1200距离、移动时间约0.8秒，范围超过800后每增加约30距离再增加一步。实际初值、路径判定和计时器执行需在目标图验证，不应把1200或对应速度作为所有技能默认值。路径条件检查局部 x1/y1，再于通过条件后更新坐标；首轮 x1/y1 的具体初值及该判断的游戏效果尚未验证。

每次移动枚举250范围的存活敌人，先加入本次技能的单位组再伤害，因此同一次飞行重复覆盖同一单位时由此组去重；排除原目标的条件被禁用。结束分支让视觉马甲播放 death，清除其逆天自定义数据，安排0.5秒后移除，并在结束分支清空、销毁命中组及清理计时器；是否显示完整动画以实际模型为准。制作相似投射物时，命中组应属于每次独立释放，结束或提前终止时均要有清理路径，具体是否允许一轮重复命中按技能要求确定。

视觉模型路径在此分组内由固定字符串拼接后交给马甲设置模型；在当前读取的 FQA148 分组中未见本地玩家特效开关判断。这不能证明地图其他层完全没有控制，也未作游戏验证。新技能优先对接目标图既有特效开关，只改变已验证安全的本地视觉表现，不能以此改变同步伤害、单位组、计时器或随机数。

## 逐日剑法：伤害、飘字与嵌套暴击标记

在当前只读 GUI 的逐日剑法命中分支中，先把局部“伤害”和按玩家编号读取的全局 `ShangHai_BaoJi` 标记传给 `display_TX`，随后才由分裂单位对命中目标执行伤害。显示模块根据收到的数值格式化浮动文字，并不会自行确定这次攻击实际扣除的生命。怪物受伤模块还存在受伤加深、减伤、无敌和闪避等处理，因此不能仅凭“已传入计算伤害”就认为飘字一定等于该目标的实际扣血；玩家对魔斧剑飘字已明确要求显示实际扣除生命。事件发生顺序、原生减免和不同监听器如何结合仍须游戏核验，此处不是对所有技能已经出错的断言。

逐日剑法在启动效果前把公共计算结果读入局部伤害，但显示暴击样式的值在延时命中时才从同玩家的全局标记读取；同一玩家期间如果进行了其他伤害计算，或者本次计算内发生嵌套，标记可能不再属于该次技能。新的技能系统应以该次技能或该次命中的明确上下文保存伤害来源及暴击结果，在目标伤害真正结算后的适当时点显示所需口径的数值，不能简单拿全局数组的最新值代替本次结果。如何区分事件进入伤害、修改后的事件伤害、原生减免及实际生命减少（包括过量伤害和治疗交错），要按目标伤害系统定义并通过测试验证。

**逐目标增伤**：逐日剑法的公共伤害计算发生在直线枚举命中之前，已读调用中的“怪物”传参动作禁用；公共计算的部分 BOSS 加成则按输入怪物的单位类型判断。作者已确认逐日剑法与此前确认的玄铁剑相同：按每个实际受击目标各自判断 BOSS 增伤，同次释放共享一次技暴判定。因此不能把这一段一次计算后的数值直接视作已经为每个目标分别完成对应增伤；具体局部变量继承与其他伤害入口是否补充修正尚待验证。新技能可将一次释放的随机技暴及玩家侧基础结果保留，再对每个合格目标应用对应目标修正，避免为每个目标重复随机技暴或重复触发技暴副作用。参考图狩猎标记名称还有作者确认的“是狩猎怪”与代码读取名称差异，不能照搬未经核对的键。

## 逐日剑法：冷却与入体进度是两件事

参考【UI【法宝】→ UI2 → 物品 148】中逐日剑法说明写“技能暴击10次后自动入体”；【直接获得法宝 → 法宝特殊入体需求】根据该物品类型的需求数量初始化物品次数，参考图该物品需求为10。【display_Jibao → FQA148 → 加物品次数和自动入体】位于“已拥有且冷却中=0”的分支内，触发逐日剑法时，检查绑定英雄是否携带对应物品，然后将该物品剩余次数减1；到0后标记已吞噬，并调用直接入体模块。

作者确认：**只有触发逐日剑法才计入该法宝的10次入体进度**；冷却期间发生其他技能暴击，不因这一事件增加进度。因而界面“技能暴击10次”的文字不足以准确表达这一规则，制作类似说明时应写清“触发逐日剑法10次”，并核对物品已替换、英雄更换、内置冷却变化、拥有与入体状态等边界。用户确认的是设计意图；当前代码所见与其方向一致，计数、入体和联机游戏仍需实测。

## 尚需用户解释或实际验证

- **琉璃瓶（FQHC30）门槛已确认**：作者确认应读取玩家“技暴几率”并判断 ≥80%；吞噬后在发生技能暴击时，再按 1% 几率增加 1% 技暴伤害。普通暴击 90%、技暴 20% 不满足门槛；普通暴击 10%、技暴 80% 满足门槛，但仍需实际发生技暴且通过 1% 判定。当前编辑器启用 GUI 比较局部 `暴击几率`，`Dislpay_Sh` 则读取 `技暴几率`，运行 `display_Jibao` 的已读参数只显式传 `玩家`；此处应核对该局部值的来源与实际行为，不能凭变量名单独断言运行结果。制作时按用户原本设计从玩家属性系统读取技暴几率，并避免把普通暴击和技暴混用。
- `FQA148` 在调用公共伤害计算前先设置冷却标记，且之后对该伤害计算指定了 `伤害类型A=2`；结合计算模块的暴击分支，冷却标记可能也有防止本效果立即重复触发的用途。这只是推测；需要用户确认设计初衷，并实际测试调用/递归与并发。
- `FQA148` 的 `time` 在已查看代码中只在 `技能冷却1 > 0` 分支设置；为 0 或未传入时逆天局部变量的初始值/继承机制和实际冷却需要核实，不应直接断言一定是 4 秒或一定为 0。
- 调用分组、计时器捕获的各局部键、共享 `ShangHai[id]` 和 `ShangHai_BaoJi[id]` 在同一玩家多次快速或嵌套触发时如何隔离/覆盖，必须在隔离测试图里验证。没有验证前不要把静态结果称为并发安全。
