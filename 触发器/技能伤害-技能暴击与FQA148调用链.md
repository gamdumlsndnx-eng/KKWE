# 技能伤害专题：技能暴击与 FQA148 被动

分析对象为《一剑爆开天门-带物编》的隔离转换结果；路径均在 `source-analysis/converted-lni-diagnostic-2/trigger` 下。以下只记录静态可见内容；LML 的转换正确性、逆天运行触发的分组/参数传递、并发、游戏伤害和显示都尚未通过源码编辑器与游戏验证。

## 一条可复核的调用链

用户说明：这一套公共模块通常只需要捕捉并传入玩家，随后根据玩家身上的自定义属性获取所需数据；玩家容易获得，所需参数较少，便于复用。用户说技能暴击是稀有属性，并提到有暴击几率门槛；由于当时未打开地图，琉璃瓶中 `暴击几率` 与 `技暴几率` 的具体对应关系暂未确认。这里是用户说明的设计思路，不能据此断言每个模块都只需玩家、也不能认定该具体变量是错误或已正确继承。

1. `03-【一些触发传输/01-Dislpay_Sh__计算伤害__.lml` 没有独立事件（1–3 行），模块从逆天局部键读取 `s`、`玩家`、`伤害参数`，由玩家计算 ID；`伤害参数` 为 0 时改成 1（71–103 行）。接着按玩家自定义属性读取各类伤害与技暴状态（104–169 行）。这是复用的计算模块，不是每个技能各写一套伤害公式。
2. 同文件“技暴几率”段 1329–1383 行：先将 `ShangHai_BaoJi[id]` 设为 0；取 1 至 100 随机整数；满足局部 `伤害类型A = 2` 且随机数不大于 `R2I(技暴几率 × 100)` 时，将该玩家的暴击标记设 1，将当前局部 `伤害` 乘局部 `技暴伤害`，再调用 `display_Jibao`。调用动作中明确传入的局部参数是玩家，条件模式为 `tirggerexecute_notcondition`。这只是该段公式，不代表已理解完整伤害公式或暴击概率边界。
3. `03-【一些触发传输/03-display_Jibao__技暴传输__.lml` 无事件（1–3 行），读取玩家、转换玩家 ID、按玩家读取绑定英雄（4–22 行）；下面以“收纳盒”组织不同技能暴击后附带效果，按玩家 ID 与物品键查询已拥有、已吞噬等状态。它既处理独立加成，也可继续调用消息、属性、计算伤害和视觉模块，而不只是画暴击数字。
4. 该文件 109–149 行的 `FQA148` 段：字符串 `玩家ID + FQA + 148` 的 `已拥有` 为 1 且 `冷却中` 为 0，才把 `冷却中` 写为 1。注释说明技能暴击后沿直线造成攻击力伤害，基础冷却 4 秒。149 行之后从玩家自定义值获取分裂单位；冷却部分读取 `技能冷却1`，在该值大于 0 时将 `time` 设为 `4 × (1 - 技能冷却1)`，启动单次逆天计时器，结束时把同一个字符串对象的 `冷却中` 写回 0 并清理计时器（150–202 行）。
5. 同一被动在 203–296 行根据玩家 `伤害类型` 选择计算模式 `s=1` 或 `s=11`，运行 `Dislpay_Sh`，显式传 `玩家`、`伤害参数=1`、`伤害类型A=2`、`伤害类型B=2` 等；另有另一组子动作以及禁用的 `怪物` 赋值，必须在 KKWE 界面核实对应分组，不能把静态缩进直接当成已确认的调用次序和返回值。后续从 `ShangHai[id]` 读取到局部 `伤害`。
6. 该被动以绑定英雄位置、朝向和单位攻击范围建立视觉单位、单位组及移动逻辑；周期 0.02 秒、每步 30 坐标单位移动，并以 250 为半径枚举附近单位（297–498 行）。对敌方、存活且不在已命中单位组的单位，先入组，再将目标和伤害传给浮字模块，接着由分裂单位对目标施加伤害（500–579 行）。排除原怪物的条件是禁用状态（522–526 行），不能称为会排除原目标。
7. 周期结束分支中的直接移除视觉单位动作禁用，实际可见的是播放死亡动画、清空该单位自定义值、0.5 秒后移除单位、清空并销毁记录组、清除计时器（582–604 行）。这是源码主动处理单位与组生命周期的例子。

## 尚需用户解释或实际验证

- `display_Jibao` 的“技能暴击几率≥80%”被动（23–108 行）实际比较局部键 `暴击几率`，而调用方计算使用的是 `技暴几率`，且上面可见的调用只显式传了 `玩家`。用户当时未打开地图，不能确认这里的对应关系；是否有其他调用链或局部变量传递仍需在实际编辑器核对，静态文本不足以判定。
- `FQA148` 在调用公共伤害计算前先设置冷却标记，且之后对该伤害计算指定了 `伤害类型A=2`；结合计算模块的暴击分支，冷却标记可能也有防止本效果立即重复触发的用途。这只是推测；需要用户确认设计初衷，并实际测试调用/递归与并发。
- `FQA148` 的 `time` 在已查看代码中只在 `技能冷却1 > 0` 分支设置；为 0 或未传入时逆天局部变量的初始值/继承机制和实际冷却需要核实，不应直接断言一定是 4 秒或一定为 0。
- 调用分组、计时器捕获的各局部键、共享 `ShangHai[id]` 和 `ShangHai_BaoJi[id]` 在同一玩家多次快速或嵌套触发时如何隔离/覆盖，必须在隔离测试图里验证。没有验证前不要把静态结果称为并发安全。
