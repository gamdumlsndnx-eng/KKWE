# 冰雨剑、三道激光和 BOSS 双圈眩晕的 T 触发写法

证据来自《一剑爆开天门》版本 9803、保存计数 6052 的启用 GUI，另核对物编与参考编辑器代码。示例供新图或后续明确授权的调整使用。编号依目标分类顺序安排，原图的触发器、变量和游戏逻辑保留。下文把源码中可见的动作与后续制作时的验收点分列。

## 冰雨剑

【Meimiao100】每 0.10 秒按有效玩家调用【Meimiao100b → BMJR7】。有本命剑且内置冷却就绪时先启动 `(8 − 固定减秒) × (1 − 百分比缩减)` 的玩家技能冷却，再以 `s=15` 和 `0.75` 调公共伤害计算。用英雄实际射程枚举候选，从未选索引段随机交换并选取不同单位。落点数上限为候选数，参数是基础 1 加每满 2 点弹射增加 1，商城再多选 1 个落点。

逐落点保存目标当时 XY。每处创建六个周边和一个中心的特效并安排约 1 秒移除，另有一次约 0.80 秒后的结算，枚举该位置 300 内存活非建筑敌方单位，由玩家马甲给伤害，随后清当前落点计时器。跨落点可重复命中。作者确认每处应有两波、每波按 75% 智力基础参数，当前启用动作只找到每处一次伤害。同处第二波的间隔须按实际制作需求确定。当前没有候选时，已启动的冷却和公共计算不会因未选到目标而撤回。

示例命名为 `12-1   【冰雨剑-周期施放】`。由公共周期调用。若落点结算会复用，可另设 `12-2   【冰雨剑-落点结算】`，接收该处坐标与本次伤害参数。收纳盒建议如下，注释放在对应盒子开头。

| 收纳盒 | 按当前动作写的注释 |
| --- | --- |
| 【内置冷却与伤害参数】 | 本轮先锁玩家的 BMJR7，再算一次伤害。启用基础参数为 75% 智力。 |
| 【随机选取落点】 | 本轮选不同目标的位置，最多选到候选数。商城多选一处。 |
| 【创建特效与延时结算】 | 在记录的坐标创建特效。0.8 秒后重新枚举 300 范围，落点重叠时各自命中。当前每处一次伤害。 |
| 【回收落点资源】 | 落点回调清自己的计时器。特效按创建时安排的寿命回收。 |

复用玩家组、伤害马甲和公共伤害输出即可。新图若需要全局名，使用 `Game_ActivePlayers` 等已有公共入口名。冷却留在玩家与 BMJR7 的状态键。候选数组、落点 XY、单次计算的伤害和技暴标记、特效与计时器都随这轮施放或各落点保存。当前飘字在给伤害之前，且读取共享暴击数组，注释不要写成“实际扣血”或“本次技暴已锁定”。如新图要求无目标不触发，应先完成选点，再启动冷却和有技暴副作用的计算。

## 三道激光

【shanghai → 英雄伤害】筛选模拟英雄伤害马甲 `e002`，把玩家、绑定英雄、伤害马甲、受击单位等传给【shanghai3 → BMJSSR9】。拥有且冷却就绪时锁住玩家技能状态，以 `(8.50 − 固定减秒) × (1 − 百分比缩减)` 安排清标记，再用 `s=15`、`3.20` 计算伤害。首轮从英雄位置朝原受击单位发三道，相对基准方向依次为 `0°、+25°、−25°`。每道约每 0.02 秒推进 30，枚举当前位置 220 范围内的存活敌人。先记入本轮命中组，再给伤害。到步数限制或飞行地形条件不满足时结束该道，删除该道特效并清计时器。

20% 概率约 0.50 秒后发第二轮。源码从保存的英雄引用读取当时坐标，沿用首轮基准方向和已算伤害，另建本轮的去重组，所以同一怪第二轮可以再中。当前两轮各由编号等于发射数的那道清除共享组。各道有独立终止条件，后续制作可让每道结束时扣减本轮尚存道数，降到零后再释放同一个组。现场尚未验证不同结束顺序的表现。原启用命中条件检查敌对与存活，此处未见排除建筑的条件，注释按该实际条件写。

示例命名为 `12-3   【三道激光-伤害入口】`。将一轮三道的工作复用于两轮时，可抽 `12-4   【三道激光-发射一轮】`，由伤害入口和第二轮回调调用。

| 收纳盒 | 按当前动作写的注释 |
| --- | --- |
| 【锁内置冷却并计算伤害】 | 基础参数是 320% 智力。两轮沿用这次计算的伤害。 |
| 【发射三道并按轮去重】 | 同一轮三道共用一组。目标第一次命中时先入组，再给伤害。 |
| 【延时发射第二轮】 | 20% 几率。0.5 秒后读保存英雄的当前位置，沿首轮基准方向发射。第二轮另建命中组。 |
| 【结束弹道并回收命中组】 | 每道回收自己的特效和计时器。原图由编号等于发射数的弹道回收本轮命中组。 |

玩家与技能的内置冷却保持玩家键。施放玩家、方向、伤害及技暴结果应随本次释放保存。去重组和尚存道数属于一轮，弹道坐标、特效和计时器属于一道。并行的多位玩家与多轮不能共用一个全图 `Laser_HitGroup`。复用全局公共伤害输出时先取得本次所需结果。当前飘字仍从共享暴击标记读取，改写时应按当前技能确认每轮、每段和每个目标的技暴及目标增伤规则。

## BOSS 两次圆圈眩晕

【BossJN_Set】将 `BOSS_JN1[5]` 设为 `A02B`。`BOSSA5` 监听 `JYDamageEvent`，来源单位有该技能且造成正数伤害，并且本体内置冷却和共用施法间隔都空闲时启动。两个锁分别存在 BOSS 单位上。参考参数为 15 和 12，遇到 `JN_Debuff[11]` 先对参数做整数除二。实际解锁由各自每秒计数器决定。触发时暂停 BOSS，读取目标坐标并创建首圈预警，共用的伤害以 BOSS 最大攻击和这一轮乘数计算。

约 1.6 秒时若 BOSS 存活，第一圈在首圈坐标枚举 440 内存活、敌对且非建筑单位，马甲给伤害，再让临时单位添加 `A02K` 并下达风暴之锤命令。第一圈解除暂停动作处于禁用状态。约 1.8 秒时再次读取原受击目标当前位置并播放第二圈预警。再延时约 1.6 秒，只有 BOSS 存活才解除暂停并结算第二圈。作者确认中途死亡时仍显示第二圈，跳过第二圈伤害和眩晕。每圈预警创建时都排入 1.8 秒移除，命中特效和临时施法单位分别约 1 秒回收。此触发的启用树中，两个冷却计时明确调用清理，三段一次性预警及命中计时器未见显式清理。后续制作须在成功和跳过分支都核对清理，运行期是否自动回收待验证。

示例命名为 `13-1   【BOSS两次圆圈眩晕-伤害入口】`。若提取两圈共用结算，可另设 `13-2   【BOSS两次圆圈眩晕-单圈结算】`，传入当圈坐标与结算条件。

| 收纳盒 | 按当前动作写的注释 |
| --- | --- |
| 【本体冷却与共用施法间隔】 | 两个状态按这一只 BOSS 保存，两个计时器分别解锁。 |
| 【第一圈预警与结算】 | 使用首次记录的目标坐标。结算时检查 BOSS 存活，第一圈不解除暂停。 |
| 【第二圈预警与结算】 | 先重取目标位置显示预警。伤害回调才检查 BOSS 是否存活，已死就跳过伤害和眩晕。 |
| 【回收预警与施法马甲】 | 预警各自按创建时安排的寿命移除。临时施法单位独立回收。 |

复用 `BOSS_JN1`、预警与马甲配置等公共内容。新图才考虑 `Boss_SkillIdBySlot` 等全局配置；每只 BOSS 的锁仍各自保存。BOSS 和原受击单位引用、两圈坐标、伤害及各阶段的计时器均属本次施放。物编 `A02K` 的名称写“风暴之锤2秒”，实时修改表未见伤害和两类时长覆盖。参考库的 `AHtb` 一级基础有伤害且英雄和普通单位时长不同。注释可写“命中后命令马甲施放 A02K”，其仅控制且英雄、普通单位均约 2 秒属于作者设计，须通过物编和游戏核对，不能把模板名当成验证。

## 与 KKWE 内部代码的对照

- `frontend_wtg.lua` 将 `YDWERegionMultiple` 识别为带一组子动作的节点，而逆天计时器有两组动作。用收纳盒组织真实动作，写注释时区分计时器的参数和到期动作。相同触发器内已有的局部值按当前 KKWE 的规则使用，需要固定的落点、共享组或跨触发数据才按需传参。
- `YDTrigger/Hash.h` 的 `YDLOCAL_3` 以 `GetExpiredTimer()` 为父键，`Timer.h` 的参数绑定也按计时器句柄保存和读取。这解释了为什么注释要写清作用域。每道回调拥有自己的计时器，但同一轮可以传入同一个单位组。清掉当道计时器的局部表，与销毁整轮共享的单位组是两个动作。编辑器 `YDWETimerStartFlush` 的说明是删除当前逆天计时器并清缓存。
- `YDWETimerSystem.j` 的 `YDWETimerRemoveUnit` 与 `YDWETimerDestroyEffect` 把句柄排入共享延时任务，分别回收单位或特效。`UnitDamageTargetBJ` 在 `blizzard.j` 中把参数交给原生 `UnitDamageTarget` 并返回布尔值。技能收纳盒内分别说明伤害、显示、控制和资源清理的实际时点。当前三个样本已核对 T、物编和库代码，仍需游戏验证连发、重叠、多人、缺目标和中途死亡。
