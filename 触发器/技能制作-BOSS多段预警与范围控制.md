# BOSS 多段预警、范围伤害与控制：GUI 制作规范

用途：按源码中已启用的 GUI 比较同构技能，设计可复用的多段落点、预警、伤害、范围控制与清理。下列数值和技能标识只属于《一剑爆开天门》样本，不作为其他地图默认值。本文是编辑器只读追踪与作者确认的设计，不代表已实现公共模块或完成游戏、多人验证。

## 本轮覆盖

已读普通 BOSS `BOSSA2`、`BOSSA3`、`BOSSA5`、`BOSSA6`、`BOSSA8`、`BOSSA9`、`BOSSA11`，存档 BOSS `CundangBOSSA3`、`CundangBOSSA4`、`CundangBOSSA6`、`CundangBOSSA9`、`N5Debuff14` 的启用动作及部分嵌套；另追踪普通 BOSS `BOSSA17`、`BOSSA18`、`BOSSA19` 的主要计时器、控制和清理路径。数量代表读取的样本，不代表各触发的全部分支已经理解。

## 二次和三次捶地是同一类机制

【BOSS技能 → BOSSA9（捶地三次）】、【存档BOSS → CundangBOSSA3（捶地2次）】、【存档BOSS → CundangBOSSA6（捶地3次）】有相同的基本流程：伤害事件筛选携带相应技能的来源和正数伤害；记录 BOSS、目标与所属玩家；检查 BOSS 对象上的自身内置冷却和技能间隔；建立预警，等待后以对应玩家的伤害马甲对范围中的符合条件单位伤害；后续阶段使用周期计时器并结束时恢复 BOSS 状态。

- 三个样本的 `num` 分别为 3、2、3；应把段数作为配置，不能为两段、三段各重写一套。其他差异如特效尺寸、伤害、冷却和目标筛选也应独立配置，不要假定只改 num 就完全相同。
- 首段以当时目标坐标创建预警，约 0.8 秒后对预警位置进行范围结算；之后的落点路径会尝试枚举合格英雄并随机选择，缺少候选时有随机坐标的分支。结算时仍要根据实际代码及逆天计时器的数据传递核对预警点与伤害点一致。
- 样本可见的目标过滤为敌方、存活、英雄、非建筑；一般技能不必照搬“只伤害英雄”，应由目标地图需求决定。
- 样本伤害在释放时按 BOSS 攻击、技能倍率、类型上存储的暴击伤害和图内倍率计算；特定难度的 DEBUFF 还可放大伤害或缩短冷却。这是参考图的 BOSS 结算，不是玩家技能公共伤害公式。
- 内置冷却和跨技能最低间隔是两个用途；作者已确认后者用于限制 BOSS 技能同时施放、控制玩家压力。样本代码把两个状态键放在 BOSS 身上并分别计时。实作时需检查同一单位多个技能的并发及旧计时器清理对新状态的影响。

## 多方向、多落点与共享命中

【存档BOSS → CundangBOSSA9（前方多方向圈炸）】启用的 GUI 将 `num1=3` 作为方向数，`num2=5` 作为每个方向的落点数、偏移角度40度；嵌套循环按方向和距离生成预警点，0.8 秒后按相同几何方法重复计算落点并枚举伤害。距离步长为 420，检测半径为 350。伤害循环在一次延时动作内创建共同单位组，合格敌人伤害前加入组，结束后销毁，因此一轮中重叠落点不会重复伤害同一目标。

可复用的结构是：方向配置 → 每方向落点配置 → 预警 → 延迟 → 按同一坐标规则结算 → 根据需求进行每轮或每个落点去重 → 清理。是否允许落点重复伤害由具体技能确定：另一技能允许不同落点独立命中时，不能照搬本样本的整轮共享单位组。预警和结算的角度、距离、目标坐标快照及模型朝向应一起核对。

## 范围控制与多人重叠

【BOSS技能 → BOSSA17（时光之门）】在英雄位置创建预警与持续特效；延迟后开始 0.1 秒周期，在范围内暂停符合条件的敌人并加入单位组，结束时遍历组恢复、销毁组并移除特效马甲。作者确认设计希望控制范围跟随英雄脚下的特效；本次 GUI 中被枚举的范围中心读取的是此前保存的 BOSS 坐标，与特效所在的英雄坐标可能不同，属于静态差异，尚未游戏验证，也未修改地图。

做类似技能时，应明确“取英雄位置一次作为固定落点”还是“持续跟随移动中的英雄”，不能仅凭作者这次回答替后续需求推断；预警、伤害和控制需共享约定中心。多人或多只 BOSS 重叠控制同一目标时，各实例直接暂停和解除暂停可能相互干扰；需按目标图实现可验证的状态归属、重叠解除与单位死亡/移除处理，而不是任一计时器结束都无条件解除全部控制。

【BOSS技能 → BOSSA18（剑影留痕）】包含周期预警、延时落点伤害和结束时单位组清理；【BOSS技能 → BOSSA19（树界）】包含范围伤害、暂停、后续周期伤害与解除暂停。这些只确认了已读的主要结构，伤害间隔、组归属及多个实例交错仍需继续追踪和实测。

## 面向制作的检查

1. 根据需求选择触发时机：伤害来源是 BOSS、BOSS 自身受伤，或其他事件；不要把所有 JY 伤害事件都按同一主客体解释。
2. 确定阶段数、每段预警和伤害位置、延迟、预警模型和大小、目标过滤、伤害马甲及去重范围；相同机制参数化，行为不同则保留单独策略。
3. 每次释放、每个计时器和控制实例要有明确数据归属；注意逆天局部变量/数组的传递范围，不把本地图的函数、字符串键和技能 rawcode 当作其他地图已有接口。
4. 每个正常结束、施法者死亡、目标移除、提前中断和重叠结束路径，分别核对暂停恢复、计时器、单位组、预警/特效马甲及临时数据的清理。单次计时器在某些已读路径中未看见显式 `YDWETimerStartFlush`，是否由接口自动释放需核查函数实现或实测，不能仅此断言已泄漏或已安全。
5. GUI 读回、保存编译、游戏单人和多人重叠是不同验收层次；本次只读学习不等于均已通过。
