# 技能制作：击杀召唤、死亡爆炸与分裂

适用：设计击杀计数、召唤物继承与伤害结算、怪物死亡后的预警爆炸或分裂。来自《一剑爆开天门》源码备份中启用 GUI 的只读追踪；分清作者确认的设计、可见动作和尚待游戏验证的行为。单位 ID、技能编号、时间和数值是本图样本，不直接用于其他地图。

## 进攻怪击杀触发召唤：完整链路

【中心系统 → JGGuai_dad → 进攻怪 → YX9】在筛选进攻怪及相应技能后，把计数绑定到玩家对应键；每累计5次归零，用局部坐标 `x1/y1` 创建属于该玩家的召唤物，并调用传送圈效果模块。作者确认设计的出生点是死亡怪物的位置；本次尚未找到 `x1/y1` 的可靠赋值位置，当前效果是否符合设计仍待追踪和游戏验证。召唤物每秒从绑定英雄读取攻击范围和攻速，在本图样本中按 `max(英雄攻击范围, 500)` 设置攻击范围、按 `max(英雄攻击范围, 1500)` 设置索敌范围，并同步攻速。默认时长变量60，玩家符合对应 FQHC56 条件时设为90；具体有效秒数与计时器起止边界仍需游戏测试。

同一召唤物计时器调用【一些触发传输 → Display_ZhaoHuan1（单个召唤物瞬移）】：模块根据召唤单位所属玩家重新找绑定英雄，距离至少800时，将召唤物移到英雄附近、播放传送特效并发出停止命令。到期分支给召唤单位设置0.1秒限时生命、运行【Display_ZHWJ（召唤物渐隐）】，并清理该周期计时器。

渐隐模块包含暂停召唤物、按0.1秒周期逐步调透明度、结束时清除单位逆天自定义数据并移除单位的动作；条件分支还可能在渐隐前延迟。上述限时生命与渐隐是先后调用，不足以仅凭 GUI 证明游戏中一定完整播放渐隐，需单独测死亡、单位移除及特效显示。跟随判断、玩家掉线、英雄更换、召唤物提前死亡及重复召唤也需要分别验证。

## 召唤伤害接入中心系统

【中心系统 → ZH_shanghai1（召唤伤害）】以 JY 伤害事件及单位类型筛选本图的传奇战士、传奇法师和 YX9 召唤物，在本分组将原事件伤害设为0；之后根据召唤物所属玩家查找绑定英雄和玩家的伤害马甲。YX9 分支根据玩家伤害类型选择本图模式，向公共【Dislpay_Sh（计算伤害）】传玩家、目标、倍率和伤害类型，读取计算结果后由马甲对目标造成伤害；传奇战士/法师分支会对范围内目标结算。这样保留地图已有的属性和伤害来源约定，不能仅用一次固定数字伤害冒充公共计算。

进一步追踪【ZH_shanghai1 → FXA01 传奇战士 / FXB08 传奇法师】：二者分别使用 s=1 和 s=11，倍率 1.00，伤害类型 A=2、B=1，并把原受击目标作为参数调用一次公共计算；之后在原受击位置的 400 范围枚举存活敌方单位，由玩家的伤害马甲分别给伤害。每次给伤害后，GUI 读取该被枚举单位生命，若不大于零，则传玩家及力量 1.00 给属性加减模块；这不是根据召唤物自身属性单独结算的机制，也不是直接把原事件伤害原值用作范围伤害。生命判断与死亡事件、其他伤害监听器、重复击杀和多人交错的实际顺序尚需游戏验证。

注意这个样本先以原目标调用一次计算，再把结果用于所有范围目标。作者已明确某些范围技能要求每个受击目标分别判断 BOSS 增伤，而整次释放共享一次技能暴击；制作有这些要求的新技能，应将施放时快照及本次暴击结果与每目标修正拆开，不能简单复制该样本的一次计算结果或对每个目标重新随机暴击。该用户确认针对对应技能的设计，不足以直接认定本召唤技能在参考图里的所有目标修正均已验证。

复用时应先确认目标图的计算器契约、伤害事件时机、马甲与玩家归属、递归保护、击杀奖励以及单体/范围和每目标结算规则；本次静态追踪不能证明多人交错、所有伤害监听器顺序或反作弊逻辑已经正确。

## 杀敌触发属性收益：区分房间归属与实际击杀者

【中心系统 → JGGuai_dad → 本命剑 → BMJSR+2 镇岳剑】与物品 `I04U`：对已拥有技能的收益玩家进行 1～100 随机判断，基础 20%，指定商城效果加 5 个百分点；成功时把该玩家的“杀敌力量”加到玩家力量，并创建短时提示特效。它是一次额外的属性收益，不是把怪物所有金币、经验和技能伤害直接翻倍。技能自己的石坠伤害在【shanghai2 → BMJSR+2】另行处理，不能因技能有死亡收益就漏掉伤害入口。

死亡入口先读取死亡怪、击杀单位及其所属玩家；对于本图四个玩家专属敌对阵营的怪，当前可见分支会改为取怪物所属玩家上保存的“绑定玩家”，后续在符合入口及击杀者阵营条件时用该玩家查技能拥有和发收益。作者确认：甲击杀乙练功房的怪时，镇岳剑这项收益属于乙这个练功房所属玩家。中立敌对怪、离开玩家、空击杀来源或其他类型的归属不能照此推断，需按地图规则核对；不同地图也不自动沿用本图敌对玩家编号。

石坠分支依据该玩家该技能累计杀敌数，目标上限为 `6 + 整数(技能杀敌数 / 30)`，先造成选中单位的技能伤害，再读取该单位生命判断是否增加该计数。物品还写低于 15% 生命的斩杀；本次所查分组及部分公共伤害、怪物受伤入口仍未找到完整的 15% 处理，作者也记得可能在受伤或计算相关触发。不能仅凭“伤害后生命不大于零”认定已实现斩杀；须继续追踪其他入口和测试，未改图。开发类似效果时要分清技能击杀计数、常规击杀收益、房间归属、精英/BOSS 斩杀限制和正常死亡奖励，不要直接删除目标绕过这些流程。

## 怪物死亡预警爆炸

【中心系统 → JGGuai_dad → N5+DEBUFF+3】先保存死亡坐标、死亡怪所属阵营的伤害马甲与按该怪攻击计算的伤害，在死亡点显示约2秒的警告，然后在保存的落点对500范围内符合敌对、存活且非建筑条件的单位造成伤害。怪物死亡触发底部会清理该怪逆天自定义数据；延时效果应在清理前保存之后真正需要的坐标、伤害、来源和玩家信息，避免两秒后依赖已经销毁的单位数据。实际计时器变量传递、来源有效期和归属需在目标图验证。

按用户最新约定，BOSS 技能默认预警和延迟；针对其他怪物死亡效果，是否预警与延迟仍需按技能要求和地图设计判断，不自动把本样本的2秒用于所有效果。

## 死亡分裂：不要把“继承”理解为复制一切

【中心系统 → JGGuai_dad → N5+DEBUFF+5】采用专用小怪模板，复制死亡怪的模型和缩放等外观，并设置最大生命为原来的三分之一、护甲、攻击和攻击范围，再创建3只。作者已确认这张地图的设计是**只继承基础属性和外观**，不继承原怪特殊能力；因此不能以“其他一样”的旧分组文字推断要复制全部自定义状态、Debuff 或死亡分裂能力。三个单位的归属、奖励、额外状态及是否允许再次分裂，应按目标地图物编和需求逐项核对，不自动假设。

## 新技能制作检查

1. 明确击杀来源和归属：英雄、伤害马甲、召唤物是否都归到正确玩家；区分死亡怪所属阵营与击杀者所属玩家。
2. 每个玩家、召唤实例独立记录次数、时长与生命周期；已被用过的持久状态在正常结束、提前死亡和移除时核对清理。
3. 按需求选择创建点、跟随阈值、属性实时同步或快照、目标过滤、伤害计算和是否复用已有模块；不得假设目标图已存在相同 rawcode、键或函数。
4. 对死亡爆炸保存结算上下文，并核对预警与实际落点及范围；对分裂明确只复制哪些字段，检查子单位奖励及递归。
5. 区分编辑器静态阅读、保存编译、单人游戏和多人并发；本次只进行了只读分析。
