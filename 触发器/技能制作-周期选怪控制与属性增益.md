# 技能制作：周期选怪、控制和属性增益

用途：参考《一剑爆开天门》制作周期自动施放、随机选敌、附加控制和临时或范围属性。依据启用 GUI 的只读追踪及作者确认，不代表已在其他地图实装、编译或测试。参考图的键、rawcode、玩家阵营与数值不是其他地图默认值。

## 本轮范围与证据等级

只读比较【中心系统 → Meimiao100（每0.1秒中心计时器）】下 FQA44、45、46、51、52、53、54、161，以及 FQHC41、42、43 的相关启用分支；另对照【中心系统 → shanghai2（本命剑伤害R-SR）】下 BMJR4、6 和 BMJSR4、5、7、8、9、10。已阅读各样本的关键条件、数值、动作和部分子分支，并非完成每个触发器的全部调用链和实战验证。分组标题是定位辅助，旧说明不等于设计或当前实现。

## 自动技能：周期、目标和冷却

【Meimiao100 → FQHC41/42/43】按玩家和对应技能状态运行，在0.1秒中心计时中累计各自计数；达到需求后选目标。已读的 FQHC41/42 分支在找到有效候选时才把计数清零并释放，因此范围内无目标时不是简单按每个冷却周期空放。计数、需求以及目标是否存在应作为独立规则，针对目标图检查冷却是否允许在没有敌人时继续等待、空放或重新计时。

FQHC41 是选一点后对其周围范围结算；FQHC42 的已读逻辑在当前攻击目标活着且在攻击范围时优先它，否则从候选中随机选一个；FQHC43 有三次目标循环和首目标优先当前攻击目标的分支。FQHC43 后续循环每次从同一候选数组随机，已读循环没有删除或交换已选目标，因此不能把它当成不放回抽样；同一目标可能多次被选中。它在收集候选时检查局部单位组 `dwz`，但本次未在该分支和中心计时入口找到此名称单位组的创建或加入动作，局部作用域、其他路径及实际结果需核对，不能断言已正确去重，也不能仅凭未见创建就断言游戏必然崩溃。

FQHC42 在冷却达到后先收集候选，有候选时才清零计数、计算伤害及选目标；FQHC43 的伤害计算位于候选筛选之前，只有有候选才清零计数并施放。因此后者冷却已满但没有候选时，按当前可见动作后续周期仍会再次调用公共伤害计算；该计算有技暴及可能的后续调用，是否出现无目标时的额外效果须在隔离图核验，不能仅把计算当成没有副作用的纯算数。新技能应明确无目标时等待、是否消耗冷却及是否允许触发计算副作用。当前参考图的一部分筛选以 `Player00` 阵营为依据，新图必须核对真实玩家敌对关系。

进一步追踪可能副作用：【Dislpay_Sh → 技暴几率】若 A=2 且随机达到该玩家技能暴击阈值，会调用【display_Jibao（技暴传输）】；其中 FQA148 分支在拥有且冷却允许时可以创建直线效果，并处理该法宝携带状态下的入体次数。故无候选仍反复计算**可能**满足这一调用链，但还要满足技暴、技能拥有、冷却与物品等条件，且局部传参及计时器语义未经游戏验证，不能把“可能推进次数”描述成已经复现。作者确认 FQHC43 无敌人时应等待，直到有目标才进行伤害和技暴判定；未来实现应先确认有符合条件的目标，再执行有副作用的计算；学习阶段不修改地图。

对照【UI【法宝】→ UI2（宝物set）】的套装初始化：FQHC41 是“梼杌裂地锤”，套装说明写200%力量自适应范围伤害；42 是“穷奇碎空爪”，写250%敏捷物理单体；43 是“烛龙断江杖”，写180%智力法术多目标。41 的启用动作按玩家伤害类型选择 s=3/13，与套装说明的自适应一致，而旧分组标题只写物理。42 使用 s=4、43 使用 s=15；三者的候选、锁定目标策略和范围不同，不应只因为都由0.1秒中心计时驱动就共用固定伤害类型或同一组目标。

42 的公共伤害调用发生在选择优先目标之前，已读的逆天调用参数中没有明确把最终选中的 `dw` 作为本次目标传进计算器；43 也先计算后选目标。作者此前要求范围技能按实际受击目标判断 BOSS 增伤，同次释放共享一次技暴判定；本图这些具体分支的局部继承、目标专属修正及游戏效果尚未验证。制作类似技能应明确把目标相关修正留到目标已确定之后，不要把从其他事件残留的目标变量默认为当前目标。

【Meimiao100 → FQA46】选中攻击范围内的目标位置后延时约0.8秒，对该落点350范围枚举并给伤害；【FQA44】以英雄位置枚举500范围。二者虽然都可产生范围伤害，但中心和延时不同，适合共用候选筛选和结算步骤并分别配置落点、延迟、范围、目标规则及特效。

【Meimiao100 → FQA44 杀神领域】基础需求为中心0.1秒计时累计40次，已吞噬 FQHC18 时可见分支将基础需求改为10次；按当前玩家“伤害类型”选择 s=6/16，以技能属性参数调用公共计算，随后对英雄周围500范围符合条件的单位由该玩家伤害马甲给伤害。组标题写物理伤害，但对应【UI【法宝】→ UI2】说明写自适应，实际选择模式也随玩家伤害类型变化；不能根据旧标题固定为物理。冷却计数是玩家与技能键关联，并非给每个玩家新建一份触发。

该技能伤害参数中的 `生命1` 来自玩家自定义属性，而不是直接调用引擎的英雄最大生命。【shuxing1 → 各项增幅 → 生命】可见将力量、最大生命和生命增幅计算并保存玩家 `生命1`，再取整后设置存活绑定英雄的最大生命，并按先前百分比恢复当前生命。属性刷新、引擎生命上限更新与0.1秒技能周期不是同一动作，属性刚改变或英雄死亡时两者时序需测试。GUI 三项算术为 `100 + 生命1 × 0.15` 的参数结构；运算符编译时的结合顺序和当前运行值须按参考编辑器版本实测，不能仅凭自动转换的括号推断最终伤害。新技能应先核对目标图属性接口、快照时间、倍率和是否维持生命百分比，不能把玩家存储值一概视作实时引擎属性。

这些分支中部分冷却需求的重算动作只在百分比冷却系数大于0时执行，固定秒数减免与零百分比组合应单独核对。用户此前明确冷却缩减归零后应恢复基础冷却；新图不得假定旧系数自动清除，也不能把源码当前实现误报为已符合该要求。

## 范围计数型增益和已确认差异

【Meimiao100 → FQA45】在玩家拥有效果时先从玩家全伤害减去该技能上次保存的增量，枚举英雄周围500范围符合条件的敌人，再按数量计算并保存新增量、加回玩家全伤害。这一“撤旧值、重新统计、加新值”的结构可用于光环或周围敌人数变化的实时增益，避免每次刷新把旧增益再次累加。

作者确认该技能**最多增加30%**。目前启用分支看到局部 `数量` 设0，却递增并使用 `数量45`，并直接按 `数量45 × 0.01` 计算；本次未在该分组找到30个上限或 `数量45` 明确归零。须继续核对局部变量作用域及实际游戏结果，不能说已经证实游戏必错；制作同类技能应明确每次重新置零和限制最多30个，保证其他增益不被覆盖。

## 本命剑：按当前数量重算属性贡献

【各种收益获得/属性加/回血/增幅 → shuxing1 → 本命剑】每1秒循环玩家处理已拥有的技能。BMJR6 根据当前“多重数量”计算敏捷贡献；BMJR9 根据当前“弹射数量”计算智力贡献。它们都先从玩家当前属性扣除该玩家该技能上一次保存的贡献，再按当前数量算新贡献、保存并加回。例如多重从2变为3，每数量提供50敏捷时，这项贡献应由100替换成150，而不是每秒再加150；其他来源的敏捷需要保留。每个玩家、每个技能的旧贡献必须独立存放，且要核对数量变化、技能失去、英雄更换和初始化为零的处理。

同一分组的 BMJSR3、6、9 分别依据当前“套装吞噬数量”和对应剑数量，计算力量/敏捷/智力以及减伤、多重伤害或弹射伤害；各属性的旧贡献分别存储、撤销并重算，商城强化还有独立的增幅贡献。作者确认【BMJSR9 紫电剑】每把智力剑增加的弹射伤害是 **5%**；启用动作乘0.05，物品 I051 及分组所写8%是旧说明。数值和套装规则是参考图专属，新图按需求配置。当前看见的重算动作都处于“已拥有”条件内；技能失去或商城效果取消后，旧贡献由哪条路径撤销尚未追全，不应宣称已经处理。

这一“撤旧值、按当前依赖重算、加新值”适合实时随装备或计数变化的持续加成；和有独立到期时间的叠层、或者释放时固定数值的快照增益不同。要避免读取包含自身贡献的属性后形成非预期自增；若依赖其他技能计算结果，还应定义刷新先后和短暂延迟，并在多人游戏中验证。

## 命中、冰冻与持续状态

【Meimiao100 → FQA51 寒光】的周期投射物移动时使用单位组排除已命中过的单位，结束分支销毁特效、清空并销毁该组及清理计时器。已读子分支对碰撞单位 `xdw` 做存活检查和伤害，但冰冻暂停与特效使用局部 `怪物`；作者确认应冰冻**本次被命中的单位**，持续**2秒**。分组说明的1秒为旧值或与当前设计不一致；这两种局部单位是否相同应逐路径核对。重叠冰冻或其他暂停效果如何互不干扰、死亡或提前移除时如何恢复，要在目标图设计和测试。

【Meimiao100 → FQA52 雷禁】有移动、碰撞、按项目单位组去重与结束清理；作者确认当前效果为命中时10%几率本次伤害翻倍，旧分组中5%几率麻痹1秒不适用。【FQA53 焚炎】包含初次伤害与0.33秒周期后续伤害；作者确认设计还包括5%受伤加深，命中后持续到怪物死亡，不同玩家或多个区域对同一只怪只生效一份、不叠加。本次在已读技能分组未找到相应状态写入，应继续追踪其他入口及验证，不能认定当前已实现。【FQA54 天毒】在受击单位没有该状态且仍存活时保存状态和玩家归属。作者此前确认天毒持续至死亡、首位施加者保留，怪物死亡统一清理其逆天数据及绑定特效。相似的技能移动外形不意味着它们的状态、持续期、归属、组去重和重复命中规则一样，必须分别追调用链。

焚炎同类玩法应区分“区域内周期伤害”和“被命中怪物身上的持久受伤加深”：多个来源检查同一目标状态，避免重复添加该效果；伤害事件按实际受击目标读状态并与其他来源的受伤修正按目标图规则合并，死亡时清理。本图【jianshang_Guai】已读到的是一次伤害的局部“受伤加深”，不能不经核对就宣称已有可直接调用的持久受伤加深接口。

雷禁与焚炎的命中去重也需分开：源码中 `dwz52` 的创建、加入和销毁出现在 FQA52 雷禁，但 FQA53 焚炎的首次范围伤害也检查该组。作者确认两个技能应**各自独立命中**；这一跨技能单位组引用是否在游戏中造成漏伤仍待验证，未修改源码。制作同类技能时按技能或释放实例持有命中组，不复用其他技能的临时组作为排除条件。

【shuxingGuai → 中毒减血】每秒从中毒怪物读取“天毒玩家”，根据该玩家查找伤害马甲并运行公共计算，对当前枚举的怪物给伤害。当前 MCP 读回的计算调用子动作中，未看到明确将当前枚举目标作为参数传给公共计算，而后者有目标类型相关增伤分支；局部变量是否另有继承机制尚未验证。作者已确认 BOSS 增伤需按每个受击目标判断，因此新技能应明确传递当前目标，旧图是否受影响需在隔离图核对，不能仅凭静态结构断言错误。

## 临时属性：重算、独立层与禁止重叠

【shanghai2 → BMJR6】攻击触发后按玩家状态检查普通 `CD中` 和增益持续标记 `CD1中`；只有两者均为0才可启动。其攻速增量按本图基础值加多重数量计算，持续时间为 `5 + 多重数量 × 0.5` 秒；作者确认每个多重增加0.5秒，旧分组说明中的1秒不适用。到期扣除本次保存的增量并清除持续标记，普通冷却单独计时。因存在持续标记，即便冷却先结束也不会立刻重新开始叠加；与独立计时可叠加的 FQHC40 不是同一策略。

【Meimiao100 → FQA161 日照/月蚀】玩家拥有或吞噬任一状态即可进入，而非两项必须同时满足。它按玩家技能键累计计数，达到需求后从两个效果中随机一个并持续约5秒：日照读取触发时的回血值并加上同一数值，到期减回该次增加的数值；月蚀将全伤害加0.30，到期减回0.30。作者确认日照采用触发时增量快照：原回血100、期间其他来源增加50时，效果中为250，到期扣除当初的100后留下150；不按实时基础值重新翻倍为300。新增同类技能时，快照、实时增幅和每层独立计时不是一回事，应依新需求决定，多个实例重叠的计算也须单独规定。

作者确认：技能只有固定减秒、百分比冷却缩减为零时，固定减秒也应生效。当前 FQA161 启用动作先设置基础计数需求200（中心周期0.1秒），但只有 `技能冷却1 > 0` 的分支才把固定减秒和百分比一起代入；因此只具固定减秒时，可见路径仍使用200，与作者意图可能不一致，尚须核查其他入口和游戏测试。FQHC41/42/43 的同类0.1秒计数分支也出现同一判断；不能因为其中一项有差异就直接断言所有技能都已发生问题。新技能在百分比缩减为0时仍按规则应用固定减秒，分别处理取整、最短周期、属性变化和清理；具体下限由目标图决定。

## 受伤技能：减伤、反击与一次性回复

另只读【中心系统 → jianshang_Guai（怪物受伤）】的 N5 DEBUFF17、4、6 及【jianshang_Hero（英雄受伤）】的 BMJR3、BMJUR2 分支。怪物受伤入口筛选事件伤害大于0.10，先把事件伤害放入局部“最终伤害”；启用顺序中包含秒杀、受伤加深、DEBUFF17 减伤，然后处理无敌、闪避、伤害记录和事件伤害写回，后面还有反伤、回复和反击分组。JY 伤害事件与其他监听器的真实触发顺序、嵌套伤害和死亡前后关系仍需游戏验证，不能仅按列表推断引擎已结算完毕。

- DEBUFF17 在对应单位携带技能、随机判定命中时，将局部最终伤害乘0.7；属于对当前伤害的减免，不是再创建一笔反向伤害。
- DEBUFF4 在符合技能、生命比例及未使用状态条件时，将怪物生命**设置为最大生命的70%**并记该单位已使用。作者确认是设到70%，不是在当前生命上再加最大生命的70%；一次性状态绑定的是这只怪，而非玩家或全图。
- DEBUFF6 读取怪物的状态标记，符合条件时以怪物攻击参数让其阵营的伤害马甲攻击来源玩家的绑定英雄，并把该怪状态置位，2秒后清除；本次只确认 GUI 的条件与写入，不将标题中的词视为完整伤害类型或多人实测结果。具体是否对同怪不同玩家共享冷却，由状态挂在该怪身上的写法及实际运行验证。
- 英雄受伤 BMJR3 是独立的受伤反击并调用中心伤害，BMJUR2 则按玩家状态累计护甲和受伤值、达到条件后清除并爆发；作者此前确认基础上限20时先累计20次、第21次再爆发。伤害来源、计数、临时增益撤回和正常死亡奖励都要随具体技能分别设计。

制作时将释放条件、目标数和单轮/跨轮重复、伤害来源和每目标修正、控制归属、持续时间、增益回退与清理分开；优先复用目标图已有的等价模块，以逆天传参承接玩家和技能实例。编辑器静态读取、保存编译、单人和多人游戏是不同验收层次。
