# 技能制作：周期选怪、控制和属性增益

用途：参考《一剑爆开天门》制作周期自动施放、随机选敌、附加控制和临时或范围属性。依据启用 GUI 的只读追踪及作者确认，不代表已在其他地图实装、编译或测试。参考图的键、rawcode、玩家阵营与数值不是其他地图默认值。

## 本轮范围与证据等级

只读比较【中心系统 → Meimiao100（每0.1秒中心计时器）】下 FQA44、45、46、51、52、53、54、161，以及 FQHC41、42、43 的相关启用分支；另对照【中心系统 → shanghai2（本命剑伤害R-SR）】下 BMJR4、6 和 BMJSR4、5、7、8、9、10。已阅读各样本的关键条件、数值、动作和部分子分支，并非完成每个触发器的全部调用链和实战验证。分组标题是定位辅助，旧说明不等于设计或当前实现。

## 自动技能：周期、目标和冷却

【Meimiao100 → FQHC41/42/43】按玩家和对应技能状态运行，在0.1秒中心计时中累计各自计数；达到需求后选目标。已读的 FQHC41/42 分支在找到有效候选时才把计数清零并释放，因此范围内无目标时不是简单按每个冷却周期空放。计数、需求以及目标是否存在应作为独立规则，针对目标图检查冷却是否允许在没有敌人时继续等待、空放或重新计时。

FQHC41 是选一点后对其周围范围结算；FQHC42 的已读逻辑在当前攻击目标活着且在攻击范围时优先它，否则从候选中随机选一个；FQHC43 有多目标循环和首目标优先当前攻击目标的分支。具体不同目标是否允许重复、每目标效果及单位组归属仍应逐项核对，不能因为都叫随机技能就直接照搬。当前参考图的一部分筛选以 `Player00` 阵营为依据，新图必须核对真实玩家敌对关系。

【Meimiao100 → FQA46】选中攻击范围内的目标位置后延时约0.8秒，对该落点350范围枚举并给伤害；【FQA44】以英雄位置枚举500范围。二者虽然都可产生范围伤害，但中心和延时不同，适合共用候选筛选和结算步骤并分别配置落点、延迟、范围、目标规则及特效。

这些分支中部分冷却需求的重算动作只在百分比冷却系数大于0时执行，固定秒数减免与零百分比组合应单独核对。用户此前明确冷却缩减归零后应恢复基础冷却；新图不得假定旧系数自动清除，也不能把源码当前实现误报为已符合该要求。

## 范围计数型增益和已确认差异

【Meimiao100 → FQA45】在玩家拥有效果时先从玩家全伤害减去该技能上次保存的增量，枚举英雄周围500范围符合条件的敌人，再按数量计算并保存新增量、加回玩家全伤害。这一“撤旧值、重新统计、加新值”的结构可用于光环或周围敌人数变化的实时增益，避免每次刷新把旧增益再次累加。

作者确认该技能**最多增加30%**。目前启用分支看到局部 `数量` 设0，却递增并使用 `数量45`，并直接按 `数量45 × 0.01` 计算；本次未在该分组找到30个上限或 `数量45` 明确归零。须继续核对局部变量作用域及实际游戏结果，不能说已经证实游戏必错；制作同类技能应明确每次重新置零和限制最多30个，保证其他增益不被覆盖。

## 命中、冰冻与持续状态

【Meimiao100 → FQA51 寒光】的周期投射物移动时使用单位组排除已命中过的单位，结束分支销毁特效、清空并销毁该组及清理计时器。已读子分支对碰撞单位 `xdw` 做存活检查和伤害，但冰冻暂停与特效使用局部 `怪物`；作者确认应冰冻**本次被命中的单位**，持续**2秒**。分组说明的1秒为旧值或与当前设计不一致；这两种局部单位是否相同应逐路径核对。重叠冰冻或其他暂停效果如何互不干扰、死亡或提前移除时如何恢复，要在目标图设计和测试。

【Meimiao100 → FQA52 雷禁】也有移动、碰撞、按项目单位组去重与结束清理；【FQA53 焚炎】包含初次伤害与0.33秒周期后续伤害；【FQA54 天毒】在受击单位没有该状态且仍存活时保存状态和玩家归属。作者此前确认天毒持续至死亡、首位施加者保留，怪物死亡统一清理其逆天数据及绑定特效。相似的技能移动外形不意味着它们的状态、持续期、归属、组去重和重复命中规则一样，必须分别追调用链。

## 临时属性：重算、独立层与禁止重叠

【shanghai2 → BMJR6】攻击触发后按玩家状态检查普通 `CD中` 和增益持续标记 `CD1中`；只有两者均为0才可启动。其攻速增量按本图基础值加多重数量计算，持续时间为 `5 + 多重数量 × 0.5` 秒；作者确认每个多重增加0.5秒，旧分组说明中的1秒不适用。到期扣除本次保存的增量并清除持续标记，普通冷却单独计时。因存在持续标记，即便冷却先结束也不会立刻重新开始叠加；与独立计时可叠加的 FQHC40 不是同一策略。

【Meimiao100 → FQA161】满足玩家拥有与吞噬状态后，按计数随机选择两个分支之一并持续约5秒：一支读取当时的回血值并加上同一数值，到期减回该数值；另一支全伤害加0.30，到期减回0.30。其回血分支是读取时的增量快照，不能自动解读为持续期间所有新回血属性都被实时翻倍；是否要实时跟随由新需求决定。重复释放、技能失去、英雄更换和计时器交错的清理需测试。

## 进一步对照的本命剑

BMJR4、BMJSR5 使用多重数量影响目标数量；BMJSR4/8 为直线或目标位置范围伤害；BMJSR7 的作者确认伤害为275%及冰爆210%，冰冻期间死亡时按最后冰冻玩家结算一次；BMJSR9 作者确认0.5秒一轮。BMJSR8 已读 GUI 传入2.85，而旧分组写2.30；这里只记录当前参数和文字不同，尚未向作者确认最终设计，不擅自改源码或当作已验证结果。

## 受伤技能：减伤、反击与一次性回复

另只读【中心系统 → jianshang_Guai（怪物受伤）】的 N5 DEBUFF17、4、6 及【jianshang_Hero（英雄受伤）】的 BMJR3、BMJUR2 分支。怪物受伤入口筛选事件伤害大于0.10，先把事件伤害放入局部“最终伤害”；启用顺序中包含秒杀、受伤加深、DEBUFF17 减伤，然后处理无敌、闪避、伤害记录和事件伤害写回，后面还有反伤、回复和反击分组。JY 伤害事件与其他监听器的真实触发顺序、嵌套伤害和死亡前后关系仍需游戏验证，不能仅按列表推断引擎已结算完毕。

- DEBUFF17 在对应单位携带技能、随机判定命中时，将局部最终伤害乘0.7；属于对当前伤害的减免，不是再创建一笔反向伤害。
- DEBUFF4 在符合技能、生命比例及未使用状态条件时，将怪物生命**设置为最大生命的70%**并记该单位已使用。作者确认是设到70%，不是在当前生命上再加最大生命的70%；一次性状态绑定的是这只怪，而非玩家或全图。
- DEBUFF6 读取怪物的状态标记，符合条件时以怪物攻击参数让其阵营的伤害马甲攻击来源玩家的绑定英雄，并把该怪状态置位，2秒后清除；本次只确认 GUI 的条件与写入，不将标题中的词视为完整伤害类型或多人实测结果。具体是否对同怪不同玩家共享冷却，由状态挂在该怪身上的写法及实际运行验证。
- 英雄受伤 BMJR3 是独立的受伤反击并调用中心伤害，BMJUR2 则按玩家状态累计护甲和受伤值、达到条件后清除并爆发；作者此前确认基础上限20时先累计20次、第21次再爆发。伤害来源、计数、临时增益撤回和正常死亡奖励都要随具体技能分别设计。

制作时将释放条件、目标数和单轮/跨轮重复、伤害来源和每目标修正、控制归属、持续时间、增益回退与清理分开；优先复用目标图已有的等价模块，以逆天传参承接玩家和技能实例。编辑器静态读取、保存编译、单人和多人游戏是不同验收层次。
