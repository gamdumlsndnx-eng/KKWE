# 多方向投射物：同一套逻辑适配不同技能

用途：用户要求多方向冲击波、剑气、激光等技能时，先判断是否是同一运动与命中机制的参数变化；优先复用符合目标地图实际接口的 GUI 模块，不因数量或角度不同就重写整套触发。本文依据《一剑爆开天门》源码启用 GUI 与用户反馈，例子是设计方法，不表示已在新图实装或完整验证。

## 需求变化：哪些可以共用

对共同的直线投射物，可按技能配置：发射数量、基准方向来源（英雄面向/英雄至目标/指定点）、角度分布及间隔、起点、移动步长或速度、距离、模型和朝向、碰撞范围、伤害参数与技能类型、每个目标的命中上限、终点动画和清理。入口负责获取玩家、英雄与触发目标，再调用公共发射模块；模块循环产生投射物，向每个逆天计时器显式传递本实例参数和伤害/暴击快照。

例如同一个“朝前扇形”模块，可以用 3 道、相邻间隔 25° 得到基准角左25°、中间、右25°；改成 2 道时可以按同一间隔对称到左12.5°与右12.5°。这是**对称分布示例**，不是用户所有技能默认角度：若指定其中一道正对目标、两道分别偏左/右、向后发射、角度总宽而不是相邻间隔，应按需求重新设置。常用计算是以序号 `i=1..N`，角度 = 基准角 + `(i - (N+1)/2) × 间隔`；环形均布可用 `360°/N`。GUI 中尤其注意整数除法和奇偶数量；两种计算方式不能把两道错误重叠在正前方。方向来源与视觉模型自身正向也要分别核对。

只有数量/扇形角度不同可主要通过参数复用；若改成追踪、往返、落地、阶段持续伤害、不同去重或不同施法者死亡规则，应复用共同部分并实现对应策略，不能仅改数量就声称行为等价。不确定“反向”是背后180°还是多个方向时，结合上下文理解；只有方向影响结果且无法推断时再询问。

## 源码对照：三道、十道和直线

- 【中心系统 → shanghai3 → BMJSSR+9 三道激光】当前分支设 `num=3`、角度间隔25°，使用奇偶序号在基准角两侧交替计算，各道由0.02秒逆天计时器推进；启用的伤害参数3.20，作者确认320%，旧分组文字260%不是当前数值。作者确认同一轮三道激光共享命中记录、目标每轮最多命中一次；双重释放的第二轮可再命中。
- 【中心系统 → shanghai4 → BMJUR+1 七星龙渊】使用相近的数量/奇偶角度结构，当前 `num=10`、间隔36°；作者确认是10道，旧文字12道过时。这两个例子说明可以提取多方向生成共同逻辑，但原图并未因此证明已经存在一个可直接复用到任意地图的公共投射物模块。
- 【中心系统 → shanghai2 → BMJR+8 长河剑气】通过中心伤害计算获得本次伤害，以0.02秒计时器每次推进30距离并沿途枚举目标；在启用的停止分支播放 `death` 动画、等待0.50秒删除马甲，同时清空并销毁命中单位组、清除计时器。紧邻的立即 `RemoveUnit` 是**禁用动作**，不能算作当前运行步骤。模型是否有相应动作及实际淡出效果需在目标图里验证。
- 【中心系统 → shanghai4 → BMJUR+4 乾坤逆轮】包含出去与返回两个阶段，并在转换阶段清空单位组；它的命中策略与单程直线不同。另见【闪电链＋多重射＋弹射＋万剑诀贝塞尔曲线 → d1（御剑杀敌_杀死敌人打原地）】：作者确认目标死亡后剩余剑只保留原地视觉效果，不对周围其他敌人补伤害。

进一步追踪乾坤逆轮：物品 `I05H` 与启用 GUI 均写 18% 触发、140% 攻击力物理伤害；由【shanghai → 英雄伤害】以本图模拟英雄伤害来源触发相应本命剑模块，再检查玩家是否拥有该技能和随机数。动作按英雄至受击目标角度建立视觉马甲，以 0.02 秒计时器前进，每步 30；先将攻击范围限制在 1200～3000，再换算去程步数，去程枚举半径 200、回程半径 230。去程按实例组记录目标，到转向处清空该组，回程允许同一目标再次被记录和伤害；结束分支播放 Death、安排约 0.3 秒后移除马甲，清空和销毁单位组，并清理计时器。源码的贴图模型 `6c0a2879d41562a4d7749f66eeea986b.mdx` 的动画表确有 death，也引用多个导入贴图；是否完整播放、实际速度、阻挡和多人交错仍须游戏验证。

玩家已说明：警戒圈等不需要死亡表现的模型正常情况下可直接删除；玩家技能特效大部分有死亡动画，按需求播放，没有死亡动画就直接删除，不以缺少 Death 认定模型有问题。对于往返、追踪或可能被障碍中断的技能，仍需分别设计单位组、模型、计时器及提前结束路径的归属，不能把任何一种视觉结束方式推广到全部特效。

## 同一剑技的普通与强化形态

【中心系统 → shanghai3 → BMJSSR+5 木马牛】经上游模拟英雄伤害相关入口调用，按玩家与技能状态检查拥有，随机命中15%后在该玩家技能键增加剑意计数；计数达到5时转入强化分支并清零。普通巨剑和强化天门之剑都朝英雄至触发目标方向移动，使用各自创建的马甲、逆天周期和命中组，但不是简单替换模型：普通形态每0.02秒前进30、沿途300范围按本次组去重；强化形态每0.02秒前进10、沿途350范围，按计数每20个周期清空一次组，因此持续接触的目标可在不同去重周期再次被命中。二者结束分支均播放 death、安排0.5秒后移除马甲、销毁组并清理计时器；阻挡、接触时长和同一目标实际命中次数仍需游戏验证。

普通分支以 s=4、参数2.20计算敏捷物理伤害；强化分支 s=4、参数1.00，作者已确认强化每次为100%敏捷，物品旧说明中的200%不适用。作者另确认：**天门之剑击杀敌人时，每名敌人永久增加1点敏捷**。当前所读强化碰撞分支未找到加敏捷动作，其他死亡入口及游戏时序仍需核对，不能认为现有源码已实现该成长。新技能须明确归属于哪个玩家、如何确认是本技能完成击杀，并确保同一死亡只发一次奖励且接入目标图属性系统。

制作具有积攒和强化形态的技能时，计数应按玩家和技能独立保存，明确是第几次触发变形、是否重置以及多玩家并发；运动参数、单目标命中间隔、伤害基数和计数规则应独立配置。两形态共用的投射和结算步骤可复用，但若去重规则不同不能共用同一个默认命中策略。参考图普通分支调用公共伤害时未看到显式传入怪物，而强化分支有传入；目标专属 BOSS 增伤和技暴快照应按每个受击目标与本次释放规则设计，并在游戏验证。

## 技能效果与属性联动分别处理

【中心系统 → shanghai2 → BMJSR+6 裂国剑】的直线技能与【各种收益获得/属性加/回血/增幅 → shuxing1 → 本命剑 → BMJSR+6】的属性刷新位于不同触发。后者先移除本技能上次计算并保存的增益，再根据当前套装数、敏捷剑数量重算并加回；对应数值是此图专属设定。这个结构避免周期刷新时将同一份增益无限重复叠加，也让装备变化后重新计算。复用直线投射物时，要保留目标技能已有的属性、成长和装备联动，不能把它们当作移动特效的一部分而遗漏；新增技能则按实际需求对接目标图属性系统。

物编 I04Y 和分组还写了“每释放5次物理伤害+1%”；作者已确认这是旧说明，当前不需要该效果。未来实现时不要仅凭旧文本把它加回。作者此前确认当前直线伤害为 160% 敏捷，旧文本的 140% 同样过时。

## 碰撞、命中、伤害与生命周期

- 先确定去重范围：每条投射物各一次、整轮共同一次、每阶段一次、按周期多次或多个落点分别命中。组应按该规则归属并在最后一个使用者结束后销毁。原图三道激光按序号 `b=num` 清理共享组；如果各道可能因路径阻挡等原因不按序结束，不能仅凭编号断言共享组一定仍有效，需检验或使用可验证的释放计数。
- 技能伤害计算、技能暴击和目标受伤处理分开。用户已确认本示例一轮共享一次技暴判定，但每个受击目标分别判断自身 BOSS 增伤；不能对每个目标重算随机技暴。按目标图的实际伤害系统与马甲接口执行，不把单纯转发固定伤害的触发冒充完整计算系统。
- `速度≈步长/计时周期` 只用于理解；提高步长可能让投射物跳过小目标或碰撞位置，应评估碰撞半径、路径连续检测与性能。射程、阻挡、中途目标死亡、动画朝向、施法者死亡、重复释放和多人交错都要独立检查。死亡动作与延迟清除应以模型实际动画能力为准。
- 区分一次释放、每轮、每个投射物和每个目标的数据所有权；计时器参数逐项传递，局部数组不能直接穿透逆天计时器。所有特效、单位、命中组、计时器以及持久状态在各结束路径按使用权清理；只凭静态树不能证明无泄漏。

## 写入前与验收

先对照目标图是否存在同语义的模块及接口；存在时检查它是否支持所需角度、命中和伤害归属，确认无关技能不会因修改默认值而改变。不存在时创建职责清晰的 GUI 模块，避免为了抽象而在简单技能中增加没有复用价值的层。遵循用户命名、逆天局部变量和伤害系统；从 KKWE 读回调用参数、嵌套动作与物编，再由用户手动保存和测试。

至少对 N=1/2/3 和偶数/奇数角度、不同方向基准、不同目标类别、同一轮重复命中、提前阻挡、最后一个投射物结束、模型动画和多人同时施放做针对性检查；分别标注编辑器读回、编译、单人游戏和多人测试状态。参数或参考地图特定能力未验证时如实说明。
