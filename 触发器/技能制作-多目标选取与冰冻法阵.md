# 技能制作：多目标选取、冰冻冰爆与持续法阵

用于根据作者的玩法逻辑编写可编辑 KKWE GUI。以下区分作者确认的设计与源码 GUI 静态观察；未做新地图编译、游戏或多人验证。标识与模型路径只用于定位参考源码，新地图要核对自己的模块、玩家关系与物编。

## 先看启用的动作，再问真正未知的问题

作者要求：能从启用触发、条件和动作明确得出的限制，先作为当前写法理解，不重复让作者确认；遇到有效代码和物编说明冲突、代码未体现所需规则、多人归属不明或行为无法从静态结构确定时，再带“分类 → 触发器 → 技能分组”提问。禁用触发器及动作默认是旧版、备份或范例，不计入运行。说明和分组文字可能过期，需与启用动作、物编当前描述一同核对。

## 一次随机多次：允许重复和不允许重复是两种技能

- **允许同一目标多次命中**：参考【中心系统 → gongji1_Hero → FQA47】。GUI 枚举候选，三次各自从同一候选数组随机，已有候选才能执行。作者确认：没有去重时可三次打同一只怪，兼顾单体 BOSS 输出和多目标场景。写同类技能要先过滤合法目标，并明确无候选、目标死亡或移动后的行为；不能为了所谓“优化”擅自改成每目标一次。
- **按候选数量限制落点**：参考【中心系统 → shanghai3 → BMJSSR+4 落剑】。启用 GUI 把落剑次数限制为候选数与计划次数中较小者；只有一个合格目标时只落一把。使用数组抽选，第一把指定原攻击目标；之后的随机项是否包含该主目标，应按具体规则核对，不能只凭“数组洗牌”就声称所有落点必定不同。作者确认：不同落点的 300 范围即使重叠，同一怪也可分别承受每把落剑的伤害。
- **每波重新选目标**：参考【中心系统 → shanghai3 → BMJSSR+6 杀戮剑阵】。按玩家及技能保存释放计数，当前次数每满 5 次使每波目标数增加；候选数不足时只选现有目标。首波即时执行，随后以计时器周期重新枚举和部分洗牌选取，因而“同一波内抽选不重复”和“不同波可以再次选中”是不同规则。每波使用的局部数组在各自执行范围内重新建立；不要把逆天局部数组直接穿透计时器或逆天触发。伤害、技能归属及计时器并发仍需游戏验证。

提示：旧 GUI 分组称 FQA47“玄灭”、FQA48“玄斩”，而【UI【法宝】 → UI2（宝物set）】当前独有词条把 FQA47 称“玄引”、FQA48 称“玄灭”、FQA50 称“玄箭”。定位时以触发器、编号、动作和当前显示数据交叉核对，不按旧分组名称猜测是同一技能。作者确认这三种技能不吞噬 FQHC19 时也应有各自基础伤害，吞噬后可额外增伤；当前看到“额外伤害”的赋值只在吞噬条件内，未找到完整的默认值路径，须继续核对逆天变量和实测，不能据此直接断言或修改地图。

## 单次命中去重与持续飞行物

【中心系统 → shanghai → FQA48 前方直线】在每次释放中先建单位组，再沿方向多个点枚举、把命中者加入同一组，避免同次扫描重叠造成重复伤害；结束清理组。【BOSS技能 → BOSSA1 冲击波】则先预警、延时发出移动的特效单位，飞行期间用组约束重复命中，再清理飞行单位、特效与组。

【中心系统 → shanghai → FQA50 玄箭】有多条飞行特效且共享单位组，表现出的设计与每个弹体各自独立计数不同。当前 GUI 由编号最后的弹体结束时销毁共享组；如障碍等原因使各弹体结束时刻不同，其他弹体是否仍使用已销毁的组需要实测。新技能应先确定整轮最多一次、每条弹体一次还是不同落点可重复伤害，并按此选择组的作用域；共享资源应在所有使用者结束后才释放，不要只凭最后编号推断最后完成。

【闪电链＋多重射＋弹射＋万剑诀贝塞尔曲线 → d1（御剑杀敌_杀死敌人打原地）】由各玩家“分裂单位2”的伤害入口衔接，按万剑数量通过计时器发出飞剑，存活目标位置会被持续读取。作者确认：目标死亡后，剩余剑只向最后记录的位置保留飞行特效，不改为攻击附近其他敌人。技能表现、追踪、伤害来源及目标已死的伤害动作要分开检查；局部时间、特效和计时器应随各次发射隔离。

## 冰冻死亡联动：玄冰剑

参考【中心系统 → shanghai2 → BMJSR+7】、【UI【本命剑】系统 → JianXin_Set、UI1d】及【中心系统 → JGGuai_dad】。JianXin_Set 将物品 `I04Z` 和剑单位 `e00P` 绑定为 SR 第 7 项，保存名称、冷却和属性等；UI1d 使用玩家编号与物品绑定的技能标识保存“已拥有”，并向英雄添加四个共用技能槽位之一。`A00P`～`A00S` 的基础均为月刃，槽位图标由选择时的数据设置；它们是界面承载，不等于玄冰剑的全部效果。

物品 `I04Z` 的当前说明和 GUI 公共伤害参数对应初始 **275% 智力法术伤害**、冰爆 **210% 智力法术伤害**；GUI 收纳盒中的 220%/180% 是旧说明。作者确认冰冻持续的 1 秒内，即使怪物被其他伤害击杀也应触发一次冰爆；多人先后冰冻同一怪时，由**最后冰冻的玩家**归属结算，只触发一次。

当前只读到的玄冰 GUI 在初始伤害后立即判断目标是否已死亡，并在当场死亡时对周围执行冰爆；在该技能分支与所检查的怪物死亡分支中尚未找到对后续 1 秒内其他伤害击杀的完整联动。不能由此声称已完成全图搜索或游戏复现。未来实现应把状态、施加者和对应有效时间关联到目标，在死亡结算读取正确归属并消费一次，再交给公共伤害和适当马甲；考虑死亡清理先后、冰爆连锁、重复冰冻、旧计时器与其他控制重叠。伤害是否快照、精确事件顺序和多人同步需按目标地图要求核对。

## 死亡后仍持续的阵法

【BOSS技能 → BOSSA15（黑刹玄阵）】检查受伤 BOSS 的技能标识与冷却，以释放时的坐标为中心建立法阵；对 BOSS 的敌方伤害，并给 BOSS 同阵营存活单位按其最大生命的 2% 治疗，之后继续周期处理。作者确认法阵建立后，即使 BOSS 死亡也运行到结束。制作此类技能要独立保存中心、阵营、伤害来源与持续时间；施法者死亡后仍续存是此技能的明确规则，不自动推广到所有 BOSS 技能。

本专题涉及的即时死亡判断、共享单位组生命周期、逆天局部变量传参与多人交错均未进行新图游戏验证；如要改变源码，须另按用户要求使用可恢复副本，不能把设计意图当作当前实现已修复。
