# 技能制作：普攻暴击、连锁与技能形态

用途：制作普攻伤害相关的首次效果、暴击联动、额外攻击，以及同一套基础机制衍生的直线、落点和扇形技能。以下依据《一剑爆开天门》源码备份启用 GUI 与作者确认；技能键、单位类型、阵营和数值仅是参考图样本。编辑器静态追踪不等于保存编译、游戏行为或多人交错已验证。

## 普攻入口和首次效果的归属

【中心系统 → shanghai（英雄+法宝伤害）】注册 JY 伤害事件，入口筛选事件伤害大于0；英雄本体的物理事件分支再处理普攻、暴击等逻辑。实际事件处于伤害处理哪个阶段、是否最终扣血仍需目标图实测，不能把“攻击开始”“受到攻击”和“造成有效伤害后”混为同一个事件。

【shanghai → 普攻+普攻暴击 → FQA75】玩家拥有技能时，检查受击怪身上的 `FQA75` 标记，尚未触发则置位并调整本次暴击随机判断。作者确认：**同一只怪对所有玩家共用一次首次必暴机会**；甲先触发后，乙不会因自己首次攻击同一只怪再额外获得这一效果。此设计不是“每个玩家对同一怪各一次”；新技能如果要求后者，需保存玩家与目标的组合状态。怪死亡后的标记随本图单位数据清理流程处理，非死亡移除仍需核对。

## 暴击联动及额外伤害来源

本图英雄本体普攻暴击分支下，FQHC27 在技能状态和暴击率门槛符合后进行概率成长，使用属性模块增加暴击伤害；FQHC38 在普通攻击暴击时，以受击点为中心读取玩家属性、调用公共伤害计算，再通过绑定的伤害马甲给范围内合格敌人伤害。该分支使用了单位组成员检查，但本次没有证明所有组的创建、加入和销毁作用域；不得仅凭这一行断言整次范围技能绝无重复命中。FQA146 还包含玩家状态和冷却条件，用伤害马甲对主目标追加伤害。不同分支是否共用同一次暴击判定与按目标修正，应按实际技能和作者此前确认的伤害规则分别核对。

【shanghai → 英雄伤害 → FQHC21】检查拥有/吞噬状态与概率，创建模拟英雄外观的视觉单位；调用公共伤害计算后，约0.3秒通过玩家绑定的“分裂单位3”给原目标造成额外伤害。原英雄和模拟英雄伤害马甲在本图职责不同，不能用任意模型马甲替换伤害来源。作者明确：**额外攻击既可触发其他被动，也允许再次触发 FQHC21 自身**，因此有概率连续触发；不能擅自加“只触发一次”禁掉这个效果。应核对延迟结算时目标死亡/移除、玩家归属、触发器嵌套、视觉单位与计时器清理，以及游戏结束等边界；若以后用户明确要求上限再按需求实现，不虚报已完成连锁实测。

## 同类普攻技能可复用的部分与差异

【shanghai → FQA48 玄斩】以攻击方向连续采样一条直线，范围内选中敌人后用单位组防止同一技能重复命中；已读分支在结束时清空和销毁单位组。攻击范围改变可影响采样次数，不能只改变模型长度而不检查实际判定。

【shanghai → FQA49 玄破】在英雄攻击范围筛选候选目标，按次数随机选择目标位置，并在约0.3秒后对落点周围进行范围伤害。当前已读落点半径为350，分组标题写300；这是静态说明与启用值不一致，作者尚未确认哪个是最终设计，不应自行修改源码。当前随机过程允许多次选中同一候选；不同落点重叠能否分别命中应按具体技能与目标图要求决定。

【shanghai → FQA50 玄箭】生成多方向效果，0.02秒周期移动，按共享命中组进行单位检测和伤害；停止分支处理特效、计时器及共享组。单位组由某个序号的效果结束时销毁，若各效果因地形等不同时结束，应核对其他仍运行的效果是否还在使用该组，不能只按序号假设清理一定安全。

三者均检查技能状态和概率，可复用伤害计算、玩家归属、目标过滤与视觉生命周期的共通接口；直线碰撞、落点范围、扇形移动、可否重复选目标及命中去重应作为各自策略。FQHC19 与多重数量的伤害联动只是参考图分支；作者此前确认没有吞噬时这些技能也应有基础伤害，不能让未初始化的额外倍率把基础伤害变成0。

## 攻击事件和层数累积的对照

【中心系统 → gongji1_Hero】使用任意单位受攻击事件并检查攻击者为英雄，入口与前面的 JY 正数伤害事件不同。其 FQA47 玄灭分支检查概率和玩家技能状态，筛选攻击范围中的候选，并以计时器控制视觉与伤害；作者此前确认选取可重复，只有一个敌人时多次攻击可都命中它。不能把“随机3次”自动改成3个不同目标。

该攻击事件内的 FQA162 竞星以玩家技能键保存计数及相应特效，计数达到门槛后归零、调用公共伤害并进入周期伤害；作者确认当前是积累10枚、旧分组文字15枚不适用。跨触发周期、玩家分离、每枚特效、提前结束和清理应逐一核对，不能仅复制触发几率或旧描述。

同一攻击入口中的 FQHC25 具有10层上限及每层独立到期，FQHC40 是固定攻速增量各自计时；详细取值及作者确认的基础属性算法见[周期选怪控制与属性增益](技能制作-周期选怪控制与属性增益.md)与[攻击入口与独立叠层](技能制作-攻击入口与独立叠层.md)。实际制作时用户要求“造成有效伤害后”就必须选择相应伤害事件和来源筛选，不能因为参考图某个技能注册了被攻击事件就原样照搬。

## 攻击入口的追踪飞剑：选目标、伤害与清理

【中心系统 → gongji1_Hero → 武器天赋】是对攻击事件触发的追踪飞剑样例，并非通用的“造成有效伤害后”入口。当前 GUI 在玩家武器等级、天赋触发概率和新手任务状态满足时，按玩家状态设置剑数和伤害参数，通过逆天运行触发并传入玩家、目标、伤害参数及伤害类别，调用公共伤害计算，再把本次伤害和暴击结果传入后续飞剑。某成长分支先读取已有天赋增伤计算本轮参数，随后才有概率累加增伤；修改时应保留或明确改变这个先后次序。

作者确认：这个成长分组标题虽写 `YX+6`，实际属于 `YX+5`；标题是旧的。以后分析时以启用条件及作者确认的归属为准，而不能把旧分组文字直接当成另一个技能。

目标选择与表现是独立策略：以英雄为中心枚举攻击范围加200内的单位，排除英雄和本次受攻击目标、已死亡单位及对玩家1友好的单位；通过局部数组和随机交换，最多选出剑数个互不重复的候选，每个选中目标生成一把剑。因此候选不足时飞剑数量也不足，唯一敌人是原攻击目标时本分支没有额外候选；这只是参考图当前行为，做新技能须依据需求决定是否攻击原目标、能否重复选中、阵营应相对谁判断。不要把玩家1阵营写死当作跨地图或多人通用规则。

每把剑创建特效，在0.02秒周期中按特效当前位置与目标当前位置重新计算角度，并旋转角度差、移动位置；目标死亡时本分支退回到发射时记录的目标坐标，到达后仅在目标还存活时给伤害。命中结束会销毁特效并清理计时器。速度28是每周期移动距离，改周期会同时改变每秒速度和刷新频率；为了不依赖帧周期，新实现宜把每秒速度乘周期后用于移动。模型自身朝向、飞行高度和死亡动作须另行核实。

制作类似技能时，分别决定每次释放共享一次暴击还是每个目标独立判定，并按受击目标计算其 BOSS 等目标专属修正。参考 GUI 先按原目标调用一次公共伤害后复用，不能证明多目标的目标专属加成均正确；参照作者已确认的设计，技能可共享一次技暴结果，但每个受击者应分别判断 BOSS 增伤。还应检查初始距离为零时的高度除法、目标持续移动或被移除时的超时及清理、多个特效并发和本地特效开关是否影响同步；这些边界尚未通过游戏或多人测试。

## 受伤触发与怪物状态

【中心系统 → jianshang_Hero → FQA68】已读分支在玩家拥有技能、怪物没有状态标记且随机条件满足时，给攻击怪物写 `FQA68` 标记并降低攻速。作者确认降低效果**持续到怪物死亡**；本图怪物死亡统一清理该单位逆天自定义数据，但非死亡移除或目标图的清理规则仍需分别核对。

【jianshang_Hero → BMJSSR3 神剑守护】受伤时满足冷却条件才启动守护，守护期间有概率改变最终伤害并触发相应效果；作者此前确认冷却结束后需等下一次受伤启动，且重叠的新守护应重新计算3秒。旧计时器不应提前移除新一轮状态；当前源码是否满足需要多人及低冷却场景测试。

【jianshang_Hero → DEBUFF10】眩晕持续动作和7秒保护间隔分别由计时器控制；作者已确认7秒按英雄共享，不是每个怪各有一次。临时暂停、免疫或移速/攻速变化应明确受体和状态归属，计时结束只撤销本实例贡献，并验证不同控制重叠、英雄死亡/更换等情况。

## 受伤激活的守护和反击

【中心系统 → jianshang_Hero → BMJSSR+3 神剑守护】在玩家拥有技能且该技能冷却结束时，由受伤事件启动3秒守护并创建胸部特效；守护期间每次符合条件的受伤按15%判定，命中时将该次局部最终伤害设为0，并围绕攻击来源所在位置进行范围反击。反击调用公共伤害计算，参数 s=3、2.30、A=2/B=1，后由玩家技能伤害马甲伤害范围内符合条件的敌人。该分支的计算调用中未看到显式传递当前目标，按作者对每个受击目标判断 BOSS 加成的要求，新实现应明确传入实际受击单位并避免反复随机技暴。受伤监听器顺序与是否最终扣血仍需游戏验证。

作者已确认冷却结束后要等待下一次受伤才启动守护；如果新守护在旧守护结束前启动，新的一次要重新计算3秒。当前每次启动都用一个定时器结束时将玩家“神剑守护中”清零，因此旧计时器可能提前清除较新的状态，仍需实测。实现新图时应让结束回调识别当前有效实例或到期时间，同时分别释放各次特效，避免旧实例影响新实例。另从拆解资源中核实源码使用的 `JN_boss06_02.mdx.mdx` 路径确实存在；不能只因扩展名重复就认定为笔误，迁移时应核对地图内部实际路径及模型依赖。

## GUI 制作检查

明确英雄真实普攻与多重、反伤、技能及模拟伤害的来源；选择正确事件，避免误触发或切断用户要求的连锁。把一次执行的上下文放在逆天局部变量或计时器实例中，把跨调用状态绑定应有的玩家、目标或玩家-目标组合。逐项检查目标选择、同轮与跨轮去重、暴击判定时点、BOSS目标修正、模型朝向、死亡动画和释放清理；静态阅读与游戏、多人实测分开记录。
