# 技能制作：杀戮剑阵与跨触发联动

用途：制作“普攻伤害入口 → 触发范围剑阵 → 多轮随机伤害 → 按释放次数成长”，同时将技能被动属性接入现有属性系统。以下来自《一剑爆开天门》源码备份的启用 GUI 和此前作者确认，具体技能 ID、数值及玩家键只适用于参考图。编辑器只读追踪不等于已编译或游戏、多人验证。

## 从物编到玩家技能状态

【UI【本命剑】系统 → JianXin_Set】将 SSR 第6项物品设置为 `I059`、对应剑单位类型设为 `e00Y`；在物品类型保存 `str`、编号和绑定单位类型，并在单位类型保存对应物品类型。初始化还在该物品类型保存攻击增幅0.05、暴击伤害0.15及名称“戮仙”。物编 I059 说明该剑有攻击增幅、暴击伤害、每3多重数量提高暴击伤害，以及杀戮剑阵；界面文字是内容入口，具体伤害和条件应继续核对启用 GUI，不能只照物编说明写。

【UI【本命剑】系统 → UI1d（同步获得本命剑技能）】从同步事件获取玩家和选项，查对应物品类型及其保存的标识，调用属性处理，然后把玩家编号和物品类型的 `str` 拼成技能状态键并设置“已拥有”；另外还有按技能槽保存的“已拥有技能”，两类状态职责不同。只创建物编或 UI，未完成玩家状态与属性对接，技能逻辑不会因此自动完整生效；这是本图实现的关系，其他地图需核实实际接口。

## 触发入口和显式传参

【中心系统 → shanghai（英雄+法宝伤害）】在英雄伤害分组检查伤害来源单位类型 `e002` 的分支中，调用【shanghai3（本命剑伤害SSR）】，向模块显式传递玩家、英雄、怪物、伤害马甲、玩家编号、位置、攻击范围、冷却系数及伤害类型等。作者已解释该马甲用于模拟英雄攻击结算并把本命剑/法宝的结算按职责分开；不能把参考图的 rawcode 当作其他地图必然已有的标记。

【shanghai3 → BMJSSR+6】检查玩家对应技能的“已拥有”与“CD中”，释放时设置冷却状态，按 `(13秒 - 技能冷却秒数减少) × (1 - 技能冷却系数)` 得到本图冷却；另用该玩家、技能键的计数记录累计释放。实际负值、下限和极端冷却处理需按目标系统设计，不假设源码已覆盖。

## 剑阵选择与多轮伤害

启用分支每次释放把计数加1，计算每轮目标上限 `3 + 整数除法(释放计数, 5)`。它以本次事件传入的目标坐标为中心，枚举 750 范围内满足存活、非建筑、非 Player00 盟友等条件的单位，将候选依次放进逆天局部数组；再用随机索引与当前项交换，相当于对需要的前若干项做部分洗牌，最多选 `min(候选数, 目标上限)` 个。这样单轮选择不重复，不必为每个玩家或每个目标复制一套 GUI。

该分支先做一轮，后续使用0.3秒周期再次收集候选并洗牌选取；条件使用局部计数与14比较。每轮重新选目标，因此同一个目标可以在不同轮被再次选中；“每轮不重复”和“整次技能全程只命中一次”是两种不同规则。目标筛选中的 `Player00` 阵营判断是本图约定，新地图应按实际施法者阵营、目标类型和规则重写，不应当成所有地图通用。

剑阵与剑光特效使用局部模型和特效单位，安排延迟移除或销毁；计时器结束执行清理。目标在周期中死亡或移除、多人交错、局部数组在计时器作用域内的读取与清理仍需目标版本实测。技能特效可见性是显示需求，不应让本地显示选择改变多人同步的真实伤害或状态。

对照【中心系统 → shanghai3 → BMJSSR+4 落剑】：它也会在候选中不重复选目标，但选中的每个目标位置各自产生一片300范围伤害。作者确认只有一个候选目标时只落一把剑，不同剑的伤害范围重叠时，同一个怪可以被不同落点分别命中。两个技能可以共用“筛选候选、随机无重复取样”，但剑阵是直接对选中单位结算，落剑是对每个落点再做范围枚举，不能把后者的范围重复命中误去重。

## 伤害快照与目标差异

已读分支先向【一些触发传输 → Dislpay_Sh（计算伤害）】传入玩家、原目标、敏捷伤害模式、倍率1.00及技能类型，读取计算结果后，在首轮和后续轮次对选出的目标使用该伤害值。本图当前实现因此可能把原目标相关的加成带到其他目标；作者此前已确认同次释放共享一次技暴判定，但各受击目标应分别判断自己的 BOSS 增伤。新技能应将“本次释放共同的随机技暴/快照”与“每名目标独立的增伤、减免”分开对接目标图的伤害模块，不能以逐目标重复随机暴击代替。

后续计时器中的飘字读取全局 `ShangHai_BaoJi`；其间其他伤害计算是否会改写该结果，需要继续核对和多人/嵌套实测，不能仅凭静态 GUI 断言飘字一定正确或已经发生错误。设计时应明确伤害数值与暴击显示所属的释放实例和时点。

## 另一个属性刷新入口

【各种收益获得/属性加/回血/增幅 → shuxing1 → BMJSSR+6】在对应技能已拥有时，先从玩家暴击伤害减去该技能上次保存的增量，再按当前多重数量 `整数除以3 × 0.10` 算新值，保存并加回。这个按周期重算的被动属性与剑阵的伤害循环分属不同触发器。移植类似技能时须分别检查基础物编属性、周期重算的贡献、主动剑阵和技能失效时的撤销，避免刷新时无限叠加，也不要把图中“每3多重加10%”当成所有类似技能的固定规则。

## 实作检查

1. 确认玩家拥有状态、具体伤害入口、马甲来源和每次调用传参；根据需求选择攻击事件还是实际伤害事件。
2. 将候选过滤、单轮目标上限、是否允许跨轮重复、轮数与间隔作为配置；不要为玩家或目标数量复制技能。
3. 分别处理释放计数、冷却、伤害快照、逐目标修正和属性增益；核查目标地图系统是否支持。
4. 检查候选为0、少于上限、目标中途死亡、技能移除、冷却重叠、多人交错和所有清理路径，并分别记录静态读回和实测结果。
