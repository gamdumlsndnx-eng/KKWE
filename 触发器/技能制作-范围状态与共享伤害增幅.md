# 技能制作：范围状态与共享伤害增幅

用途：制作友方可进入、离开或重复进入的技能领域，并将领域状态接入地图真实伤害系统。本页来自《一剑爆开天门》源码备份的启用 GUI、物编只读结果与作者确认；仅作原理参考，未经目标图游戏或多人验证。rawcode、对象名称、范围和时间仅属于本图。

## 源码中一条跨 GUI 和物编的链路

【UI【法宝】→ UI2】把游龙登记为 WPnn_BW[158]，写入界面名称、“独有词条”和基础需求数量 1500；【UI1AA】将物品类型上的需求初始化到实际物品次数。【中心系统 → JGGuai_dad → 可增加数量的物品 → FQA158】按死亡入口已解析的收益玩家检查拥有状态和英雄实际携带，把该件物品的次数减 1，归零标为已吞噬并传“玩家＋物品”给【Dp_RTFB2】；入体模块稍后移除物品、更新法宝背包与图标。这里次数属于物品实例，拥有/吞噬属于玩家，技能说明属于物品类型，三者应分开。该路径只处理死亡入口认可的击杀，不把所有单位死亡计入。

【中心系统 → Meimiao100 → FQA158 游龙剑阵】对已拥有或已吞噬的玩家独立计数，以 150 个 0.1 秒周期为基础。达到条件后从英雄周围 250～1000 的随机距离和方向取点，最多试 10 次，再创建该玩家所属的剑阵马甲并设 5 秒限时生命。当前启用分支只在百分比冷却缩减大于 0 时才读取固定减秒；若新需求允许固定减秒独立生效，不照搬这一门槛。10 次都无可走点时，未见创建前另做失败兜底。新图应定义跳过、重选或回退，不能假定最后一个坐标必然可走。

本图马甲 `e01M` 的已修改物编技能列表含 `A096`；`A096` 使用原生光环模板 `AIae`、作用范围280、关联 Buff `B001`，目标参数包含存活、地面、友方、自身等条件。`B001` 物编说明为剑阵增伤状态。【一些触发传输 → Dislpay_Sh → FQA158】检查参与计算玩家的绑定英雄是否拥有 `B001`，拥有则把当前伤害独立乘以 `1 + 0.15`，随后还有最终伤害分组。普攻和技能只有确实经过公共计算时才走此判断；这里不再检查受益者是否持有游龙，范围内队友可由同一状态获得增伤。

作者确认：**范围内的队友也应获得15%独立伤害增幅**；光环只是提供用于识别范围状态，伤害由触发计算，**不希望额外增加原生移动速度或攻击速度**。本轮从编辑器元数据确认 `Oae1`、`Oae2` 是这两个原生字段；A096 的修改项未覆盖两者。随附的参考 AIae 一级数据为 10% 移速、5% 攻速，但当前活图未读到有效继承值，未实测是否实际附带原生加成。继续核对前，不能把提示文字当实际效果，也不能把未覆写当作已归零。

避免改出连带问题：当前物编还把 A096 挂到圣骑士、问剑天山／焚天熔炉等单位类型；后者有部分在难度设置或副本结算中创建。若以后经确认仅调整游龙，建议为它独立配光环，按需要独立 Buff，公共伤害只读约定的领域状态；同时检查同一英雄处于两个领域是否仍只乘一次。这个建议尚未修改地图。

视觉也有两层：当前“创建马甲”分组给局部路径赋了值，但未见应用该值的替换动作；实际创建 e01M 使用物编模型，另有 A096 的目标附着和 B001 的状态效果。拆解资源确认模型文件和所查贴图存在，不能由此证明三层在游戏里都显示。新图对接本地特效开关时仅控制呈现；光环马甲、状态与伤害仍要同步创建和清除。

## 可复用设计，不照搬原始 ID

1. 定义领域的施放者、创建位置、半径、持续时间、受益阵营与有效单位类型；明确离开、回到范围、施法者死亡或多领域重叠时的规则。队友受益仅是本案例已确认设计，不代表其他技能默认相同。
2. GUI 创建领域并保留实例数据；可用无额外原生数值的光环状态辅助识别，或使用经验证的范围枚举。无论采用何种方式，都要处理光环刷新延迟、目标死亡及领域结束，不能仅依赖视觉特效表示增益。
3. 若状态只作为范围标识，伤害增幅应在目标图的中心计算中独立判断，不应同时把原生技能参数也配置成重复增益。先检查技能模板的继承字段、光环目标过滤和 Buff 对应关系。
4. 明确乘区和计算时机：本图例子是在技暴之后、最终伤害分组之前做独立乘法；具体技能是否享受、多人交错、目标防御和 BOSS 增伤按目标伤害系统确认。不要把“技能描述有15%”误当作完整计算或覆盖原有全伤害加成。
5. 检验多个友军、敌方、飞行单位、进入／离开／重叠领域、领域消失后状态残留及同时施放；区分 GUI 读回、保存编译、单人和多人实测。本次只做源码、物编只读核对。
