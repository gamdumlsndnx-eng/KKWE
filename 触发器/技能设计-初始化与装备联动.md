# 技能的初始化、获得与装备联动

依据《一剑爆开天门》版本 9803、保存计数 6052 的 KKWE 只读 GUI，以及本机隔离转换结果。文中的对象 ID、阵营和数值用来定位参考图。游戏与联机验证另做记录。

## 开局时分别查玩家、英雄和配置的来源

- 【地图初始化 → DayOff】在地图初始化事件中把正在游戏的人类玩家加入玩家组 `WJZ`。【Out】在玩家离开后从组里移除该玩家，并清理英雄、宝宝等相关单位。周期技能和属性刷新可以共用这套玩家范围。
- 【DayOff2】在 0 秒事件设置玩家与敌对玩家的双向关系，给玩家绑定预摆伤害马甲，包括通用伤害 `分裂单位`、多重箭 `分裂单位2`、模拟英雄伤害 `分裂单位3`。另有 `TX_MoNi` 视觉马甲类型表。制作时分别核对马甲类型、玩家名下的实际马甲、伤害归属和视觉实例。
- 难度和修仙模式由 【UI_ND2d／UI_ND2c】接收同步后，运行 【UI_ND_dp／UI_ND_dp2】。两条分支都检查并设置同一个“已选完难度”，然后运行 【hero_Set】；修仙分支在调用前更新相应传送区域。英雄的自身 0 秒事件禁用，它由这两个实际入口启动。常规难度另有 【ALL_Set1】启动进攻计时与怪物类型表的入口。
- 【hero_Set】先准备英雄类型与天赋的映射，在创建后写入玩家的“绑定英雄”、给该英雄加天赋并调用 【Display_ShuXing】记入初始属性。随后还有延时恢复上局外观、设置衣服武器与其属性的分支。普通复活走 【hero_Dad】的复活动作，目标是死亡的原英雄；换身走 【hero_display2】，由英雄系统负责属性继承。
- 数据表各自有就绪时点，如衣服武器 【YIFU_Set】的 0.5 秒事件、本命剑 【JianXin_Set】和词条 【UIf2_Set】的 2 秒事件。部分表在事件内部继续延时写入。【Meimiao100】每 0.1 秒枚举 `WJZ`，以九项局部参数把玩家、编号、绑定英雄、分裂单位、X/Y 坐标、射程、冷却系数及伤害类型传给 【Meimiao100b】。【shuxing1】每秒同样枚举 `WJZ` 并刷新属性。开局的玩家名单和英雄创建由不同入口负责。设计新的周期分支时，复用玩家名单，确认英雄、施法所需马甲和配置已经就绪，再按技能规则检查英雄是否存活。

## 本命剑如何从挑战进入周期技能

1. 【JianXin_Set】按等阶配置物品类型、剑灵单位类型与技能标识。其中 R 档第 7 项 `I04P` 的运行时配置名为“冰心剑”，标识 `BMJR7`，并有界面用的 CD 与杀敌智力属性。物编显示的原始名称可以和运行时界面不同。初始化同时给“挑战剑道传承”和“挑战本命剑入体”两个物编技能标注“是剑道技能”。
2. 【JianJN_Use】监听任意单位施法效果，按施放技能类型的上述标记进入，再区分两项挑战。可见创建动作以玩家绑定的敌对玩家为单位所有者，交给 【Display_guai_Creat】处理怪物属性。【JGGuai_dad】在本命剑死亡分组调用 【jian_Dad】，剑道挑战成功进入 【UI_BMJDP】。候选生成后按玩家编号和选项位置存入表，供同步选择读取。
3. 【UI1d（同步获得本命剑技能）】从同步发送者及选择位置查回物品类型，防止连续点击并处理奖励属性。在已读授予分支中，为 `玩家编号 + BMJJN + 槽位` 保存“技能类型、物品类型、已拥有技能”，给当前英雄添加槽位技能。另用 `玩家编号 + 本命剑标识` 保存“已拥有”。入体选择 【Jian_dhk_dianji】清除槽位的“已拥有技能”，移除承载技能并为背包增加记录。该动作处理槽位和承载，运行时效果要另查对应技能拥有状态。
4. 【Meimiao100b → BMJR+7 冰雨剑】检查玩家的 `BMJR7 已拥有` 和自身冷却，使用当前英雄射程选取落点，走公共计算及伤害马甲。启用计算是智力法术模式 `s=15`、倍率 `0.75`。作者确认每个落点应有两波，不同落点可分别命中同一只怪；本次读取的分组仍只找到每个落点的一次延时伤害。技能栏、技能拥有资格、真实冷却与效果次数都应分开核对。

## 法宝的进度与获得来源

- 【UI2（宝物set）】为 156 号法宝配置物品类型、说明与“需求数量=3”。【UI1AA】获得时登记玩家的法宝拥有状态、发放单件属性，并初始化该物品实例的剩余次数。【UI1b】同步替换另会减去旧物品属性、调用获得模块并传 `替换=1`。
- 【FQ_HeCheng】在英雄拾取满足合成条件的法器后更新套装吞噬状态与总数，再调用 【ui_DisplayGet_ShuXingTUN】。156 分支检查玩家拥有该法宝并且当前英雄携带它，扣除该物品剩余次数，归零才写“已吞噬”并调用直接入体。已读获得分支按物品配置初始化次数，尚未找到用过去已吞噬套装数抵扣的动作。总套装数量与这件物品自带的进度是两项数据。
- 156 的另一个效果在 【UI1AA】检查 `已拥有=1` 与 `替换=1`，符合物品类型限制后通过 10% 判定，对本次换到的法宝调用 【Dp_RTFB2】。同一获得入口的普通获得天赋检查的是 `替换=0`。一个公共获得模块可以接收原因参数，联动各自玩法事件。
- 【Dp_RTFB2】保存玩家、传入物品及其类型，安排约 0.3 秒后检查该物品生命，再按已读取的英雄和物品类型处理移除、背包及界面。对新图设计延时入体时，应决定它处理的是原来的那件物品，还是当前任意同类型物品。检验同类型两件、先合成、换英雄和玩家离开时，物品、状态、属性和背包记录是否对应同一次成功结算。

## 落樱天赋与时之预言的入体链

- 【hero_Set → hero_select】按英雄类型保存天赋编号和物编技能，选定后记录玩家拥有的 `YX`。落樱的承载技能是 A01H，运行条件读 `YX10`。在【UI1AA → YX10】中，普通获得且符合非特殊法宝条件时，以 15% 概率请求本件法宝直接入体。A01H 的面板也写 15%，触发器旧分组标题写 10%。替换获得另走 FQA156 的 10% 分支。
- 【UI2】为 FQA155、156、157 配置的初始次数依次是 5、3、3。合格的刷新、套装吞噬和放弃分别由 【UI1d】、【ui_DisplayGet_ShuXingTUN】、【UI1e】扣减各自携带的物品次数。三个模块都在自己的进度归零时写入该法宝的“已吞噬”，并在 155、156、157 全部已吞噬时解锁 `FQHC57`（时之预言）。
- 【UI1AA → YX10 → FQHC57】在自动入体判定成功且时之预言已解锁时，分别读取玩家底层力量、敏捷、智力的当前值，将每项的 3% 作为增量交给 【Display_ShuXing】。飘字另按对应属性增幅和三围增幅计算显示。增量写回原属性，所以后续触发会包含本技能前面发放的成长。例如忽略其他增量和显示取整，属性 100 连续两次变成 103 和 106.09。
- 本图【UI1AA】先发入体提示和三围奖励，【Dp_RTFB2】约 0.3 秒后检查原物品生命，再按物品类型搜索原先绑定英雄的背包。【FQ_HeCheng】可能先移除原物品；【UI1AA → 复活给装备】也可能将获得的物品隐藏，由【hero_Dad → 复活给装备】在复活时放回英雄背包。两种路径均需单独验证，尤其检查入体提示、属性奖励、实际消费和复活待发物是否对应同一件物品。
- 制作类似效果时，先确定成长以“抽中入体”还是“该物品成功入体”为条件。若要求入体成功才发奖励，将玩家、具体物品和来源随请求传入，在消费成功后集中写入状态、发奖励并更新界面，保证同一物品只结算一次。复活待发、合成已消费和替换也要与这次结算对齐。成长应否包含自己历史增量是独立的平衡决定。

## 衣服武器词条的授予与结算

- 【YIFU_Set】准备按等级读取的装备数据与对应 BOSS 配置。【JGGuai_dad】依据单位类型标记把衣服或武器 BOSS 的死亡交给 【YFWQGuai_Dad2】。该模块更新装备等级，经公共属性模块扣旧等级属性、加新等级属性，并刷新装备文本。打开词条界面时若还有选择在处理，则增加对应待选次数，否则调用 【Upwq／Upyf】。
- 【UIf2_Set】给正常、特殊词条配置物品类型及参数。展示模块保存玩家每个候选位置对应的词条物品类型，本地只处理自己看到的界面。同步入口 【UIf1_tb1／UIf1_tb2】用玩家和选项取回实际候选，交给 【Dp_yifqJL】。后者根据词条类型发属性或登记特殊词条的“已拥有”。
- 特殊 16 号在 【JGGuai_dad → 进攻怪】读取玩家的拥有状态，传 `木头=3` 给属性模块。作者确认限偶数波。当前 GUI 唯一可见的旧波次条件已禁用，比较式还是 `point mod 2 = 1`。该条件下方还嵌了 YX9 的飘字逻辑，YX9 实际的 2 木头与召唤计数在同级的另一个分组。若以后实现按出怪波次奖励，可在创建时把所属波次写在怪物上，死亡后读取。应核对第 2 波残怪到第 3 波才被击杀的情况，并把词条的条件限制在自己负责的奖励和显示。
- 特殊 18 号由 【Jian_dhk_dianji】在玩家选择本命剑入体时读取拥有状态，向 【Display_ShuXing】传 `全伤害=0.05`。同一套词条发放机制可以服务击杀奖励和技能成长，各自的具体结算放在能确认事件成功的模块中。

## 设计例子：武器词条解锁周期冰雨

假设新需求是选中武器词条后获得周期冰雨，每个落点两波。先给词条配置一个稳定标识及冰雨参数，再由同步选择模块登记玩家拥有状态。周期入口从玩家状态拿当前英雄和伤害马甲，使用同一个冰雨分组控制冷却、有效目标和落点。每个落点保存坐标并复用一次范围结算动作，两波分别调用；需要商城额外落点时改候选位置数量即可。

伤害仍走目标图的公共计算。如果需求指定同一轮共用技暴、不同目标各自判断 BOSS 增伤，则在这一轮确定一次技暴，把结果保存在该次释放里，命中时再按各实际目标处理。模型显示接入本地特效开关，每个落点管理自己的计时和特效；技能停用、英雄死亡或换身后的已发波次按该技能规则处理。验收可用开局首次获得、两个玩家同时选择、两个落点重叠和玩家中途退出等场景。
