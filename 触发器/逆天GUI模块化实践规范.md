# 逆天 GUI 模块化实践规范

依据：用户提供的《一剑爆开天门-带物编》源码地图、指定 KKWE 的 `share/mpq/ydtrigger/action.txt`、`call.txt` 和 `define.txt`。这是一组已查看的例子和制作要求，不表示整张地图已全部理解。源码地图和转换结果保存在本机学习目录，不上传地图或资源。

全量转换文本的字符串检索中，234 个 `.lml` 文件包含 `YDWEExecuteTriggerMultiple`，共检出 1,625 次该函数名。这个统计包含禁用项，不代表 1,625 次实际运行，也未逐一检查转换和功能；它说明跨触发器传递是需要重点学习的常见写法。

## 用户的制作偏好

- 用可继续在 KKWE 中编辑的 T/GUI；优先使用当前编辑器已注册的逆天、YDWE 和原生函数。
- 根据事件取得触发单位、所属玩家、技能和目标等上下文，传给复用模块；临时计算数据优先使用逆天局部变量，避免每个玩家配一套触发器和全局变量。
- 对多人可共用的事件，优先查找语义相符的“任意单位/玩家”等通用事件，并用事件响应取得实际对象，再判断所属玩家、条件和目标。不能忽略不同事件的适用范围：例如多个不同矩形的进入事件不一定能被任意单位事件直接替代。
- 独立触发器负责入口、条件和转发，公共模块负责同一件事情，如单次刷怪、生成后的属性处理、技能效果。不要把不同功能硬塞进一个巨大触发器。
- 用户说明：整条已关闭的触发器通常是供复制修改的常用模板，或大改前保留的备份；分析当前生效逻辑时默认优先研究启用项，不把关闭项当成当前设计或运行行为。若需要制作模板、追溯历史或发现明确调用关系，再有针对性地核对；保留用户已有备份，不擅自启用、删除或覆盖。
- 用户进一步说明：触发器内部灰色、红色齿轮标识的禁用动作可能是旧版回退、临时保留、模板或样本，实际运行不执行；禁用事件不再作为有效事件注册，禁用条件/嵌套动作的具体影响也要按所在位置和编辑器显示核对。统计、推导和实现时不要把禁用动作算入生效逻辑，不擅自启用或删除。
- 区分“整条触发器关闭”和“启用的触发器中某个事件/条件/动作关闭”。后者不能据此断定整个触发器不用：例如参考源码的进攻初始化触发器中自动事件禁用，但难度设置另有调用；仍需核实具体调用和运行条件。
- 确需跨次执行共享的数据，使用地图已有的对象自定义值或经过设计的全局配置表、数组；不能把所有全局变量一概删掉。避免照搬源码中已经禁用的动作和条件。
- 新增命名格式：分类 `12-0   【测试】`、触发器 `12-1   【攻击触发器】`，编号后有三个普通空格；现有名称由用户维护。

## 逆天 GUI 函数及参数

1. `YDWESetAnyTypeLocalVariable` 是“[逆天] 局部变量 -- 设置”，参数为类型、变量名、值；`YDWEGetAnyTypeLocalVariable` 按变量名读取。编辑器显示 `loc_玩家`，参数实际名字是 `玩家`，不要误把 `loc_` 重复写进键名。调用方和被调用模块所用名称、类型和值必须一致。
2. `YDWEExecuteTriggerMultiple` 是“[逆天] 触发器 -- 运行”，指定目标触发器和是否检查条件，子动作中设置要传递的局部变量。预设 `tirggerexecute_notcondition` 是“无视条件”，`tirggerexecute_hascondition` 是“检查条件”；实际选项应由需求决定。
3. `YDWESaveAnyTypeDataByUserData` 把类型化的值保存到对象及属性键，`YDWELoadAnyTypeDataByUserData` 从对象和属性键读取。例如以玩家为对象、`刷怪级别` 为键保存持久状态。保存与读取要对应对象、键及数据类型；还需考虑对象生命周期和清理。
4. 编辑器函数定义明确说明：逆天局部数组不能穿透逆天计时器、逆天触发器；逆天计时器和逆天注册的触发器内部不能使用等待。普通局部值跨触发和回调的并发、重入、具体生命周期仍需要在本版本做专项验证，不能只从名称推定。
5. 来源是 GUI 转换文本和编辑器定义；转换文本不一定保存足够的编辑器内部子动作分组信息。写入时要核对正确的参数结构、动作组以及 GUI 读回，不凭格式推测嵌套分组。

## 参考源码中的调用链

- 练功房入口 `09-in_LGF` 注册四个区域进入事件，检查进入单位是存活英雄，再取单位及其所属玩家；调用公共的“练功房刷怪全部”，在调用动作内传递 `玩家`。这说明同一个触发器可以服务多个入口，不说明不同矩形事件能合并成一个事件。
- `06-Display_chuguai3` 的开头读取 `玩家` 和 `s`，但上述 `09-in_LGF` 调用位置只明确传了 `玩家`；`s` 的默认或继承行为尚待验证，不能擅自假定。
- `13-Qieguai_use` 用任意单位施法效果事件和技能 `A094` 条件筛选，再从施法单位取得所属玩家；两个不同分支复用消息模块并分别传入 `s=1`、`玩家`、提示文字 `Tip`、`秒=8`。切怪状态变化与提示显示分开。
- `04-shuagua_wp` 使用“任意单位施放技能效果”入口，通过技能类型对象上的 `我是刷怪技能` 属性筛选；取得技能、单位、玩家、刷怪级别和对应区域后，枚举区域内单位。它依照怪物类型选 `Guai_LGF_Pig[刷怪级别]` 或 `Guai_LGF[刷怪级别]`，清理旧单位关联数据并移除旧怪，再运行“练功房刷怪单个”，传入 `玩家` 与单位类型 `nn`，最后清理单位组。
- `05-Display_chuguai1` 没有独立事件，先读取传入局部变量，再依据玩家自定义数据、`s` 和其他条件区分普通怪与精英。精英使用 `Guai_LGF_JY[刷怪级别]`。普通怪里从 `Guai_LGF` 赋值的同名动作处于禁用状态；精英的英雄区域判断也禁用。源码精英角度计算顺序还须核验，不应声称已确认朝向行为。
- `01-ALL_Set2` 在一次计时事件中循环玩家 1～4，检查玩家状态并建立按玩家存放的练功房配置。循环初始化不是为四名玩家复制四套相同触发器；数值和过滤条件依照具体地图需求设计。

可复核的本地转换文件位于 `C:\codex\007\KKWE编辑器学习\source-analysis\converted-lni-diagnostic-2\trigger\22-【练功房】`；例子分别为 `09-in_LGF.lml`、`04-shuagua_wp.lml`、`05-Display_chuguai1__练功房刷怪单个__.lml`、`01-ALL_Set2__练功房__.lml`。技能例子和更多细节另见本地 `源码GUI深度学习-局部变量与练功房.md`。
